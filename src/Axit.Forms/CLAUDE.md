# Axit.Forms, the shared window pieces

WinForms code every app of the bundle uses (`docs/axit/SPEC.md` AX-6.2, AX-6.4). It has no window of its own and, apart from `TextJumps`, no unit tests; the apps check it with NVDA. Nothing here references an app (M2); a piece arrived here on its second use, unchanged apart from its namespace (M3), so AxClaude's behaviour stayed the same.

- `OverlayPanel` and the records `Notice`, `OverlayChoice`, `OverlayInput`, `OverlayPreset`, `OverlaySession`: a window's own dialogs drawn inside the window in place of its main controls (AxClaude D23, bundle AX-7.2). The window shows one with `Populate`, which adds the key line made from the buttons ("Enter: Save. Escape: Cancel.", the whole text when the notice has none), sets its `AcceptButton` and `CancelButton` to `DefaultButton` and `CancelButton`, calls `FocusStart`, hides its other controls and disables its menu, and swallows its own shortcuts while the notice shows; `Chosen` tells it which button was pressed. The text and the Custom arguments field have the bundle's page and paragraph keys (`EditKeys`). A `Notice` with `Progress` shows a progress bar under the text, moved with `SetProgress`; NVDA reports it by its own settings. The New session controls (`OverlaySession`) are AxClaude's and sit here because the panel moved whole. The text takes the window's `TextJump` pairs (`Jumps`) and moves by Markdown structure through `Axit.Core.MarkdownOutline`, announcing on the notice (AX-7.2).
- `ControlArea` and `ListKeys`: one list or one field in the message field's place, named with the question, new for every question (AxClaude D33). `ShowList`, `ShowField`, `Clear`, `Hold`, `FitHeight`; the lists are `ListBox` and `CheckedListBox` (NVDA read a `ListView` as a table).
- `Sounds`: the chimes and ticks through one winmm wave-out device kept open for the life of the process, every sound prepared once and queued with a single write, and AxClaude's working music as one buffer that loops with the loop flags on a second device, so that a chime's reset never cuts it (see the gotchas in `src/AxClaude/CLAUDE.md`). `Notice()` is the one every window uses.
- `EditPaging`: Page Up and Page Down in an edit control, one screen at a time and to the ends (`EM_LINESCROLL` against `EM_GETFIRSTVISIBLELINE`, since `EM_SCROLLCARET` is ignored without the focus).
- `EditParagraphs`: Ctrl+Up and Ctrl+Down in an edit control move to the start of the previous or next paragraph (the first line, or a line with text after a blank line), and with Shift grow the selection to there (AX-8.2). The EDIT control's own keys scroll a row and leave the caret, which a screen reader reads as the same text again. The arithmetic is `Axit.Core.Paragraphs`, tested. The control hides the selection's anchor: the caret is drawn at the active end, so `GetCaretPos` against `EM_POSFROMCHAR` of the selection's start tells which end moves, and `EM_SETSEL` takes the anchor first and the caret second.
- `EditKeys`: the KeyDown handler that gives any edit control the two above (AxClaude's message field, AxDown's editor, the notice's text and field); the window subscribes `EditKeys.Handle`.
- `Announcer`: the one UI Automation notification (AX-7.1): "most recent" for the result of the user's own key, "all" for status; false without a handle, so the caller can fall back to a selection. Every window and the notice announce through it.
- `StatusLayout`: fixed widths for two status labels when their texts do not fit (an unexposed label otherwise).
- `BundleKeys` (AX-8.2): the keys that mean the same in every window; `All` feeds the collision test; `Text` spells any key the way a menu shows it ("Ctrl+Shift+S"), so that both windows' menu items read their shortcut text from the tables.
- `TextJump` and `TextJumps` (AX-7.2): a window's key pair for one kind of element in a text, with the level for headings, and the jump itself on any edit control (the pair for a key, the element from `Axit.Core.MarkdownOutline`, the caret, one announcement) plus the menu label of a pair with NVDA's letter as the mnemonic. Each window builds its pairs from its own key table (`AxClaudeKeys.NoticeJumps`, `AxDownKeys.Jumps`) and sets `OverlayPanel.Jumps`; AxDown's editor handles its keys and builds its Next and Previous submenus from the same list. `TextJumpsTests` in `tests/Axit.Tests` covers it.
- `AxitMenu` (AX-9): a `ToolStripMenuItem` every window puts before Help, `new AxitMenu(this, checkItem, updateItem, () => latestState, notice => ShowNotice(notice))`: New window with one item per app (`Dispatch.Apps`; a new process of this program file with the app's verb) and Recently closed (`Axit.Core.RecentlyClosed`, started the same way with the path); then Open windows, Open windows by type (one submenu per app) and Close all windows; then the window's Check for updates and Update to items and About, a submenu of the bundle's sections (`Axit.Core.BundleAbout`: Version with the window's latest-release state, Licence, Attribution, Axit guide, and Axit on GitHub through `UpdateCheck.RepositoryPage`), each shown through the window's notice method. The lists are refilled on `DropDownOpening` from `EnumWindows` (the visible, unowned, titled top-level windows of the processes with this one's name; Z order is recency), the current window checked, and in an empty list one enabled item that says what is missing ("No other open windows") and does nothing: WinForms skips disabled items when the keyboard moves through a menu, so a submenu of only a disabled "(none)" opened with nothing selected and NVDA read nothing (Kyle hit this; the apps' Recent lists follow the same rule). A window item restores a minimized window and calls `SetForegroundWindow`, which Windows allows because the user's key in the foreground window asked for it. Close all windows posts `WM_SYSCOMMAND` `SC_CLOSE` to every other Axit window and then to this one, so each closes as on Alt+F4 and asks its own question where it would. The lists and labels are `Axit.Core.AxitWindows`, tested.

Gotchas that live here are AxClaude's and are kept in `src/AxClaude/CLAUDE.md` (the EDIT control, NVDA's reading after a key press, the notice state as a flag in the form, `AcceptButton` for Enter, Alt and F10 as `SC_KEYMENU`).
