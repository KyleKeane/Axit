# Axit.Forms, the shared window pieces

WinForms code every app of the bundle uses (`docs/axit/SPEC.md` AX-6.2, AX-6.4). It has no window of its own and few unit tests (`TextJumps`, `AppMessage`'s text form and `BundleKeys.Text` in `tests/Axit.Tests`); the apps check it with NVDA. Nothing here references an app (M2); a piece arrived here on its second use, unchanged apart from its namespace (M3), so axClaude's behaviour stayed the same.

- `AxitForm` (AX-6.5): the window base every app's window derives from, one class in partial files, one per section. `AxitForm.cs`: the hooks a window fills in (listed under "what the window fills in"; `GitForm` is the smallest example, `TextEditorForm` the editors', `AxClaude.MainForm` the richest), the menus every window has (`CreateAxitMenu`, `CreateTextMenu`, `CreateGeneralMenu`, `CreateDeveloperMenu`, `CreateHelpMenu`, `CreateExitItem`, `Item`, `Toggle`), `OnShown` (the settings-not-read report, then the update check), `WndProc` (Alt and F10 swallowed while a notice shows, and the release of an Alt held as the window was activated, within 1.5 s, since Alt+F4 on another window left this one's menu bar open, 2026-10-23; a hand-over answered at once and its `TakeHandOver` action posted), `ProcessCmdKey` (text size keys everywhere, the find keys in a notice's text, then nothing else while a notice shows; a key from a `ToolStrip` stays the menu's, AX-6.6; F1, the palette and Ctrl+S (`SaveCommand`); then the window's `ProcessWindowKey`), `Do` (a command's task; an escaped exception becomes a notice, since an exception out of an awaited task would otherwise be unobserved), the window's place (`RestoreWindow`, saved on closing), `SaveSettings`, `ShowSystemDialog` with `DialogShowing` (every Windows dialog goes through it, since a dialog's closing activates the window; the editors and axFile wait on activation while it is set), `ChooseFolder` (the Windows folder picker), `OpenUrl`, `OpenInExplorer` (a folder opened, a file selected; `select: true` selects a folder too), `OpenSettingsFile`, `CopyDiagnostics`, `OpenBarMenu` (Shift+F10, the Applications key and a right click: the bar's menu with a letter, posted as Alt and the letter once the keys that asked are up, so that NVDA reads its first item; from axFile on its second use, axProcess, 2026-10-24). `AxitForm.Notices.cs`: `ShowNotice`, `CloseNotice`, `ShowError`, `Fail`, `Announce` (on the notice while one shows, on `AnnounceSource` otherwise; not virtual) and the one focus rule: `_focusBeforeNotice` is the innermost focused control when the first notice of a chain opens (`FocusedControl`), `_chaining` is set around a button's action so that a notice the action opens neither remembers the focus again nor calls `OnNoticeOpened` a second time, and the last close gives the focus back to that control when it is still there and visible, to `FocusTarget` otherwise. `AxitForm.Find.cs`: one Find notice (`FindNotice`) and one last text (`FindText`) behind `ShowFind(TextBox)` with `FindNext`, `ShowFind(Action<string>)` for a window with a search of its own (the transcripts), `ShowFindInList` with `FindInList` (the next item whose name holds the text, wrapping once; from axFile on its second use, axMedia, 2026-10-22), and `ShowFindInNotice` with `FindInNotice` (Ctrl+F, F3 and Shift+F3 while a notice shows, AX-7.2: the Find notice in the notice's place, then the notice shown again from `Overlay.Shown` with the match selected in `Overlay.Body`). `AxitForm.Fonts.cs`: `TextFont`, `ApplyTextFont`, `ChangeTextSize`, `UseSystemFont`, `ChooseFont`. `AxitForm.Updates.cs` (AX-3): `CheckForUpdates` (the state for About, Version set first, then one notice or announcement), the update notice, `InstallUpdate` behind one progress notice, the restart arguments kept for `OnFormClosing`, `KeepWorkingAfterUpdate`. `AxitForm.Palette.cs` (AX-10): the command palette, below. `AxitForm.Install.cs` (AX-2.9, 2026-10-24): `InstallProgram`, the Install it now of a missing program's notice: a progress notice saying whether Windows will ask for an administrator's yes, the installer run off the UI thread with a timeout, the PATH read again, the app's own check, then "Git is installed" and the app's next step, or a notice with Try again and the download page. It grew out of `TextEditorForm` on the third copy (axGIT, 2026-10-18); the notice and focus core was written again on 2026-10-23 (`docs/axit/review-2026-10-23.md` 5.3), when `FocusToKeep` and the windows' own `Announce`, `Do`, Exit items, "Nothing to save here", settings notices, folder pickers and hand-over receivers went.
- `ConsoleForm` (AX-6.5; docs/axterminal/SPEC.md AT-2; 2026-10-23, docs/axit/review-2026-10-23.md 5.1): the window of a console app on `AxitForm`, what axClaude's `MainForm` and axTerminal's `TerminalForm` had twice. One class in partial files. `ConsoleForm.cs`: the controls (`Transcript`, `Input`, `Area`, `MenuBar`, `StatusBar` with `StateLabel` and `PlaceLabel`, `RecordItem`, `RecentFoldersItem`) made and docked in the constructor, which takes the app's `LineStore` model, its `TranscriptKeys` and the two accessible names; the hooks a console window fills in (`Working` for the music, `OnTranscriptChanged` after the view, the status bar and the music have followed a change, `UpdateStatus` through `SetStatus`, `OnProcessExited`, `AskBeforeClosing` with `CloseConfirmed`, `FolderInHand` for Recently closed, `SwitchFolder` for the recent folders, `ProcessConsoleKey` for the window's own keys after the shared ones); the window base's hooks filled in for both (the chime from `SoundOnBell`, the hidden controls, `BottomControl` as the focus target, the view as `AnnounceSource`, `KeepCaret` from the control the notice opened from, the font, the update's and the settings error's system lines, `Fail` with a system line); the sealed key switch (Tab, Shift+Tab, Ctrl+Tab, Ctrl+Shift+Tab and F6 between the view and the bottom control, the find keys, the bookmark from anywhere, Ctrl+Alt with a letter reading to the end); `GoTo`, `CloseArea` (virtual: axClaude clears what it showed), the bookmark toggle; the menu item helpers both windows place (`FindItems`, `BookmarkItems`, `TranscriptTextItems`, `CreateMusicItem`). `ConsoleForm.Process.cs`: `StartProcess` (the pseudo console with the inbox posted once per burst, the recorder fed on the reader thread, the quiet timer, `LastOutputTick`; false after the error notice when it could not start), the exit settle and `OnProcessExited`, `StopProcess` (virtual: a window stops its own timers first), `Post`, `Write`, `Enqueue` and `StartWrites` over the one paced queue with one pump timer (`_pump`; a restart stops it, so no second pump runs on, which happened until 2026-10-23), `ClearWrites`, `WritesPending`. `ConsoleForm.Files.cs`: `FindDialog` and `FindNext` over the base's Find notice and the view's search, `Export` (the transcript as the reader sees it to a UTF-8 file), the recording (`ToggleRecording` from the menu, `StartRecording` for axClaude's `--record`, the stop, the failure from the reader thread). `ConsoleForm.Signals.cs`: `Signal` (the question or done chime, the alert in the background, the taskbar flash), `UpdateMusic` and `ToggleMusic`.
- `TranscriptView` with `TranscriptKeys` and `QuickKey` (docs/axterminal/SPEC.md §5; from axClaude on its second use, axTerminal, 2026-10-18; `TranscriptKeys` carries `BookmarkLine` and `ReadToEnd` for the console window since 2026-10-23): the read-only transcript of a console (axClaude's conversation, axTerminal's terminal), a `TextBox` that applies `Axit.Core.Transcript.TranscriptMirror`'s edits, keeps the caret on its line, holds output for 250 ms after a key press, places the reading breaks, and adds the single-key navigation: the quick keys and their Ctrl+Alt layer (`ReadToEnd`), `l`, `m`, Backspace, Enter on a line (`LineChosen`), Escape (`EscapePressed`), Ctrl+C with a selection, find, the bookmark jumps and `JumpToLatestResponse`. The keys are the window's: it passes a `TranscriptKeys` record built from its own table (`AxClaudeKeys.Transcript`), the quick keys as `QuickKey` data (the letter, the kind's spoken name, which lines it stops at, a rule about the line before, and `ReadsWhole` for the paragraph key), so that each window keeps its letters and the collision test sees them. The gotchas of the EDIT control and NVDA's reading after a key press are in `src/AxClaude/CLAUDE.md`.
- The menus every window has are the base's too (since 2026-10-18): `CreateTextMenu` (the window's own items, a separator, then Font…, Larger text, Smaller text, Windows text size), `CreateGeneralMenu` (Check for updates at start, then the window's own), `CreateDeveloperMenu` (Open settings file, the window's own, Copy diagnostics) and `CreateHelpMenu` (Keyboard shortcuts, User guide, a submenu of pages); `Toggle` makes a checked item for a setting that saves on each flip. A window builds its own menus (File, Edit, Navigate, …) and keeps the shared order: in Options its own submenus first (axClaude's Sounds, Speech, When Claude is done, Questions), then Text, General and Developer; the Axit menu before Help.
- `OverlayPanel` and the records `Notice`, `OverlayChoice`, `OverlayInput`: a window's own dialogs drawn inside the window in place of its main controls (axClaude D23, bundle AX-7.2). The window shows one with `Populate`, which adds the key line made from the buttons ("Enter: Save. Escape: Cancel.", the whole text when the notice has none), sets its `AcceptButton` and `CancelButton` to `DefaultButton` and `CancelButton`, calls `FocusStart`, hides its other controls and disables its menu, and swallows its own shortcuts while the notice shows; `Chosen` tells it which button was pressed. The text and the Custom arguments field have the bundle's page and paragraph keys (`EditKeys`). An `OverlayInput` may carry a `KeyHook`, asked about each key in the field first (axFile's path completion, 2026-10-22), with `InputCaret` and `SetInputText` for the window. A `Notice` with `Progress` shows a progress bar under the text, moved with `SetProgress`; NVDA reports it by its own settings. A `Notice` may carry a control of the window's own under the text (`Custom`, with `Accepts` asked before the default button acts and `HeadLine`, a first line the window changes through `SetHeadLine`; `PressDefault` for the control's Enter): the New session controls of axClaude and axTerminal are `SessionControls` with `SessionPreset`, in their own file since 2026-10-23, each app giving it its own wording, its folder picker and its announcer (they sat in the panel because it moved whole from axClaude). The text moves by Markdown structure through `Axit.Core.MarkdownOutline` with the pairs in `Jumps`, the bundle's heading letters (`TextJump.HeadingLetters`) unless the window sets more, announcing on the notice (AX-7.2); `Shown` is the notice on view and `Body` its text, so that the window base's find can put the Find notice in its place and bring it back with the match selected (`HasSearchableText`: a text without a field or a control of the window's own).
- `CommandPalette` (AX-10, 2026-10-22): `Commands` reads the window's menu bar into `Axit.Core.PaletteEntry` lines (every enabled, available leaf item under a bar item, its name from `Palette.Name`, the menus as its path, the key from `ShortcutKeyDisplayString`, "checked"), each running the item's `PerformClick` and saying a `CheckOnClick` item's new state; `FilledOnOpening` tags a submenu refilled on `DropDownOpening` so that `Commands` skips it: **a new self-filling submenu is marked where its filling is attached**, or the palette lists it as an empty leaf or with last time's items; `RefreshedOnOpening(menu, refresh)` attaches a refresh that changes items as the menu opens (axFile's Undo text, axTerminal's checked shell) and marks the menu so that `Commands` runs it before reading (2026-10-23). The palette's flow is the window base's (`ShowCommandPalette` from `BundleKeys.CommandPalette` in `ProcessCmdKey` after the menu-mode check, and Axit → Command palette, the item `CreateAxitMenu` hands the Axit menu as its first): a notice whose `OverlayInput` has `Changed` and `ListName`, so that `OverlayPanel` shows `_matches`, a list that never takes the focus, under the field (`SetMatches`, `MatchIndex`, `SelectMatch`, `MatchPage`); the field's `KeyHook` moves through the matches; the 300 ms `_paletteSpeak` timer says the first match; Run is a `StaysOpen` choice that closes the notice itself and posts the entry's action, so that the focus is back where it was (the notice rule) before the command runs. A window adds entries of its own through `PaletteEntries` (axFile's folder entries).
- `RecentMenu` (AX-9.5): `Fill` for every "Open recent …" submenu: the paths that still exist (asked of a path on a local drive only, `Axit.Core.LocalPaths`, since a share could stall the menu; 2026-10-23) as "1. name (path)" with the number as the mnemonic, or one enabled item saying there are none (`NoneWhenEmpty`, which the Axit menu's lists use too); `FillFolders` for a list of folders (Directory.Exists and `Axit.Core.PathName.Of` filled in).
- `ControlArea` and `ListKeys`: one list or one field in the message field's place, named with the question, new for every question (axClaude D33). `ShowList`, `ShowField`, `Clear`, `Hold`, `FitHeight`; the lists are `ListBox` and `CheckedListBox` (NVDA read a `ListView` as a table). `ShowList`'s optional letter hook (2.11.0) is asked about a plain letter before the list's own jump, so that a screen's named key (d to discard) acts from anywhere in the list. `KeyHold` is the one-second hold on the answering keys that the area and the notice panel share (`Start`, `Clear`, `Holding`): a control that appears while the user types must not take the next keys as its answer.
- `Sounds`: the chimes and ticks through one winmm wave-out device kept open for the life of the process, every sound prepared once and queued with a single write, and axClaude's working music as one buffer that loops with the loop flags on a second device, so that a chime's reset never cuts it (see the gotchas in `src/AxClaude/CLAUDE.md`). `Notice()` is the one every window uses; `Edge()` (a short low note, 2026-10-22; two falling an octave and louder since 2026-10-23, the one note lost under speech) is the earcon for a key that moves nothing or a typed name nothing starts with (axFile AF-3.6), where a sentence would be noise.
- `EditPaging`: Page Up and Page Down in an edit control, one screen at a time and to the ends (`EM_LINESCROLL` against `EM_GETFIRSTVISIBLELINE`, since `EM_SCROLLCARET` is ignored without the focus).
- `EditParagraphs`: Ctrl+Up and Ctrl+Down in an edit control move to the start of the previous or next paragraph (the first line, or a line with text after a blank line), and with Shift grow the selection to there (AX-8.2). The EDIT control's own keys scroll a row and leave the caret, which a screen reader reads as the same text again. The arithmetic is `Axit.Core.Paragraphs`, tested. The control hides the selection's anchor: the caret is drawn at the active end, so `GetCaretPos` against `EM_POSFROMCHAR` of the selection's start tells which end moves, and `EM_SETSEL` takes the anchor first and the caret second.
- `EditKeys`: the KeyDown handler that gives any edit control the two above (axClaude's message field, axDown's editor, the notice's text and field); the window subscribes `EditKeys.Handle`.
- `AutomationChannel` (docs/axit/automation.md, 2026-10-23): a window's automation pipe, `axit-auto-<process id>`, opened by the window base's `OnShown` only when `AXIT_AUTOMATION` is set (the test runner `tools/AxAutomate` sets it, and `AXIT_HOME` for the run's own files): keys posted to the focused control with the modifiers in the thread's keyboard state, characters, the focus, what was announced (`Announcer.Raised`), the window's state, a menu command by its palette name, close. Menu mode of the menu bar cannot be driven this way (it needs the foreground); `menu` runs the command instead.
- `Announcer`: the one UI Automation notification (AX-7.1): "most recent" for the result of the user's own key, "all" for status; false without a handle, so the caller can fall back to a selection. Every window and the notice announce through it.
- `AxitList` (AX-8.6, 2026-10-24): the list of every app, a `ListBox` with type-to-find (letters within a second one prefix through `Axit.Core/TypeAhead`, Shift with a letter backwards from `ModifierKeys`, the edge earcon when nothing starts with it, `e.Handled` so that the list box's own one-letter jump never runs; any other move of the selection starts a new search, `OnSelectedIndexChanged` with `_jumping` set around the search's own move, since axAutomate typed "s", moved, then "b" within the second and searched "sb"; a space never starts a search) and the edge earcon for Up or Home on the first item and Down or End on the last (`OnKeyDown`, after the window's `ProcessCmdKey` has had its keys), built in; `Names` when some items are not names, `ResetTypeAhead` for a list filled anew. The rename in place (AX-8.7; from axFile on its second use, axTask and axPass, 2026-10-24): `BeginRename` puts a "New name" box over the selected item, Enter hands its text to the window's commit (which calls `EndRename` when it takes it), Escape and leaving the box end it, `ended` tells the window; `Renaming` lets a window's key switch leave the box its own keys (Ctrl+Z). In axFile's folder and Actions lists, axGIT's list, axMedia's queue and axProcess's list; `tests/Axit.Tests/ListTests` fails on a plain `ListBox` in an app, its exceptions named there (the lists that never take a typed letter). The automation channel's `keys` make no typed character and its `type` no Shift, so the backward search is in the unit tests and the NVDA plans.
- `ItemForm` and `ItemKeys`, with the records `ItemRow`, `ItemDetail` and `ItemDetailLine` (docs/axit/item-apps.md; from axTask on its second use, axPass, 2026-10-24): the item apps' window on `AxitForm`. `ItemForm.cs`: the navigator and the detail pane (`Navigator`, `DetailPane`, each an `AxitList`) in a `SplitContainer`, the status bar, `PlaceControls` with the app's menu bar, the key switch of `ItemKeys` after the app's own (`ProcessItemKey`), the levels (`Into`, `OpenSelected`, `UpLevel`, `AnnounceLevel`, `Refresh`), `Fill` (the one place the navigator, its name, the title and the status bar are filled, from the app's `ReadLevel`) and `FillDetail` (silently, on every selection change, from the app's `DetailOf`; the field selected kept while the same `ItemDetail.Key` shows). `ItemForm.Fields.cs`: every field command (`CheckField`, `ChangeField` by type, with the app's `ChangeSpecial` for its own types and the Title's change through `RenameItem`; `NewField`, `RenameField`, `RemoveField`, `MoveField`, refused with the app's `FieldsFixed`; `ReadAll`), each a new `ItemDocument` handed to the app's `SaveFields`, and the notices both apps use (`AskText`, `ChooseFromList`). The app fills in the levels (`ReadLevel`, `EnterList`, `LeaveList`), the detail (`DetailOf`, `SpokenValue`), the saving, the navigator's commands (`NewItem`, `NewList`, `RenameRow`, `DeleteRow`, `Undo`, `CheckInNavigator`) and its menus (`MenuLetter`, `UpdateRowMenus`); `ItemKeys.All` is in each app's key table.
- `StatusLayout`: `Pair` makes a window's two status labels (no AccessibleName, no Spring, kept inside the strip as it resizes); `Fit` gives them fixed widths when their texts do not fit (an unexposed label otherwise).
- `BundleKeys` (AX-8.2): the keys that mean the same in every window; `All` feeds the collision test; `Text` spells any key the way a menu shows it ("Ctrl+Shift+S"), so that both windows' menu items read their shortcut text from the tables.
- `TextJump` and `TextJumps` (AX-7.2): a window's key pair for one kind of element in a text, with the kind's spoken name and the two functions that find the next and the previous element (`TextJump.Markdown` makes a pair from `Axit.Core.MarkdownOutline` with the level for headings; JSON's outline brings its own functions), and the jump itself on any edit control (the pair for a key, the element from the pair's functions, the caret, one announcement) plus the menu label of a pair with the key's letter as the mnemonic. `TextJump.HeadingLetters` (h, Shift+H, 1 to 6 with Shift) is what every notice's text takes by default (2026-10-23; axClaude's and axTerminal's tables held a copy each); an editor builds its pairs from its own key table (`AxDownKeys.Jumps`) for its text and sets `OverlayPanel.Jumps` to the letters and its pairs together, and builds its Next and Previous submenus from the same list. `TextJumpsTests` in `tests/Axit.Tests` covers it.
- `AxitMenu` (AX-9): a `ToolStripMenuItem` every window puts before Help, made by the base's `CreateAxitMenu` (`new AxitMenu(this, paletteItem, checkItem, updateItem)`; the menu shows its notices and opens the repository page through the owner's `ShowNotice` and `OpenUrl`, which are `protected internal` for it, and reads `LatestReleaseState` for About, Version): New window with one item per app (`Dispatch.Apps`; a new process of this program file with the app's verb) and Recently closed (`Axit.Core.RecentlyClosed`, started the same way with the path); then Open windows, Open windows by type (one submenu per app) and Close all windows; then the window's Check for updates and Update to items and About, a submenu of the bundle's sections (`Axit.Core.BundleAbout`: Version with the window's latest-release state, Licence, Attribution, Axit guide, and Axit on GitHub through `UpdateCheck.RepositoryPage`), each shown through the window's notice method. The lists are refilled on `DropDownOpening` from `EnumWindows` (the visible, unowned, titled top-level windows of the processes with this one's name; Z order is recency), the current window checked, and in an empty list one enabled item that says what is missing ("No other open windows") and does nothing: WinForms skips disabled items when the keyboard moves through a menu, so a submenu of only a disabled "(none)" opened with nothing selected and NVDA read nothing (the user hit this; the apps' Recent lists follow the same rule). A window item restores a minimized window and calls `SetForegroundWindow`, which Windows allows because the user's key in the foreground window asked for it. Close all windows posts `WM_SYSCOMMAND` `SC_CLOSE` to every other Axit window and then to this one, so each closes as on Alt+F4 and asks its own question where it would. The lists and labels are `Axit.Core.AxitWindows`, tested.
- `AppMessage` and `HandOver` (docs/axmedia/SPEC.md AM-1.3, AM-D4; docs/axpreview/SPEC.md AP-1.2; 2026-10-22): the hand-over between a starting process and the open window of the same app, for the apps that keep one window (axMedia, axPreview). `Send(appName, verb, paths)` finds the app's newest window through `AxitMenu.OpenWindows` and `AxitWindows.Of`, sends one `WM_COPYDATA` with the text (`Format`: the verb, then one path per line; a signature in `dwData` so that other programs' messages are ignored) through `SendMessageTimeoutW` with five seconds and abort-if-hung, first granting the window's process the right to bring itself to the front (`AllowSetForegroundWindow`) for the verbs that take the focus (`TakesFocus`: everything but `add`; the window calls `AxitMenu.Activate` on itself once the paths are applied, so that NVDA reads the new content), and returns true when the window answered 1, so that the starting process ends without a window; `Receive(ref m)` in the window's `WndProc` gives the `HandOver` back (null for any other message), and the window sets `m.Result` to 1. The verbs are constants here (`Play`, `Add`, `Open`, `Show`). `SendTo(window, …)` hands over to a window the caller found itself: axStart's is hidden, so `OpenWindows` (visible windows only) never lists it, and axStart finds it by title and program (docs/axstart/SPEC.md AS-1.2). The text form is tested in `tests/Axit.Tests` (`AppMessageTests`).
- `TextEditorForm`, `EditorApp`, `EditorKeys`, `EditorHost` (AX-6.2; docs/axdown/SPEC.md, docs/axjson/SPEC.md AJ-D4): the text editor shell, axDown's `EditorForm` until axJSON, the second editor. `TextEditorForm` (on `AxitForm`) is the window every editor app is, with the app as data (`EditorApp`: name, verb, settings file, file filter and default extension, F1 text, guide, the `TextJump` pairs of its outline, the Help resources submenu, and `EditorCommand`s on the whole text, each a function from the text to a `Rewrite`, applied as one undo step through the selection); `EditorKeys` are the shell's keys, included in every editor app's table; `EditorHost.Run` is the editors' entry point, one call into `AppHost.Run` with the one file of the command line, the settings and the window. The undo history (docs/axdown/SPEC.md AD-2.5, 2026-10-21): every `TextChanged` outside a load or a replay records the text before and after it into `Axit.Core.EditHistory` with where the key was typed (`KeyPress` for characters, Backspace, Enter and Tab, `KeyDown` for Delete; -1 for a paste, a cut, a command), so that runs merge; a one-second timer breaks the run; Undo and Redo (Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z, `EditorKeys`) apply the step through `Select` and `SelectedText` with the `_replaying` flag set and put the caret after the text put back; a reload is recorded as a step, Open and New clear the history. The whole text is read on every change (`_editor.Text`), accepted for the files the editors hold. `LoadDocument` is the read (`ReadDocument`: what the window keeps on a refusal, a missing file in the viewer, a failed read) and the showing (`ShowDocument`); the text's context menu is the window's own and the control's undo buffer is emptied after each change (AD-D1); `OnActivated` waits while a dialog closes (`DialogShowing`); the caret arithmetic is `Axit.Core.TextLines`. The viewer's own part (the read-only setup, its File items, its keys, the hand-over, Reload, Edit in axDown or axJSON) is `TextEditorForm.Viewer.cs` (2026-10-23).
- `AppHost` (AX-1.7): every app's entry point: `Run(name, logName, usage, args, window)` sets up the log and the crash handling (the report as a notice in the open `AxitForm`, or a message box without one), logs the start and the exit, answers `--help` and `--version`, and runs the window the function makes from the remaining arguments; `OnePath` reads an app's one file or folder and reports anything else; `BadCommandLine` logs and shows a message box, the only kind the bundle allows, since no window exists yet. Gotchas of the window live in the axDown notes and in the window's comments (the Ctrl+H/I/J/M guard, the word wrap handle recreation, the notice state flag).

Gotchas that live here are axClaude's and are kept in `src/AxClaude/CLAUDE.md` (the EDIT control, NVDA's reading after a key press, the notice state as a flag in the form, `AcceptButton` for Enter, Alt and F10 as `SC_KEYMENU`).
