# AxFile.Core, the pure code

Everything of AxFile that needs no window: a folder's entries, the player's rules, the one seam to Windows' media stack, the file operations, the settings. Unit tested in `tests/AxFile.Tests` over temporary folders; the player itself is checked by ear. The spec is `docs/axfile/SPEC.md` ("SPEC.md" below); the window is `src/AxFile`, with its own `CLAUDE.md`. The bundle rules are in the root `CLAUDE.md`.

## Commands

```
dotnet test tests/AxFile.Tests/AxFile.Tests.csproj
```

## Where things are

- `FolderListing` and `Entry`, `OpenWay`, `SortBy` (SPEC.md AF-2.2, AF-3, AF-3.8): `Read` (a `Listing`: a folder's entries, hidden and system ones and ones starting with a period left out unless asked and counted, folders first in natural order), `NotShownText` ("Not shown: 3 hidden, 2 starting with a period"), `Sort` (by name, date newest first or size largest first, folders first, ties by name), `Filter` (names containing a text), `Arrange` (both), `SortName`, `WayOf` (what Enter does, by the extension), `ListName` ("24 items"; "3 of 24 items, filter chap"), `FolderName`, `Information` ("report.pdf, 1.2 MB, modified …"; a drive's free space), `FormatSize`, `Parent` (null at a drive's root), `ThisPC`, `IsThisPC` and `Drives` (the ready drives as folder entries marked `IsDrive`, "Local Disk (C:), drive", AF-3.10), `Resolve` (a typed path with environment variables, a file's path giving its folder and the file).
- `NaturalOrder`: `StrCmpLogicalW` of shlwapi as an `IComparer<string>`, File Explorer's order of names.
- The media file rules (`MediaFiles`: the extension sets, `IsMedia`, `FormatTime`, `ParseTime`, the speed steps) are `Axit.Core`'s since 2026-10-22, shared with AxMedia (`docs/axit/axfile-split.md`); the window takes the media paths of a listing itself with `IsMedia`.
- `MediaPlayer` and `PlayerState` (AF-5.2, AF-D3): Media Foundation through MFPlay (`mfplay.dll`: `MFPCreateMediaPlayer`, `IMFPMediaPlayer`, `IMFPMediaItem`, declared as COM interfaces in vtable order with `PreserveSig`), one file at a time into the window handle given at creation. `Play` makes the item synchronously (a file that cannot be opened throws with the reason), sets it, and `Started` fires when the engine reports it set and playing; `Ended` and `Failed` are the other events; `Position`, `Duration`, `Seek`, `Pause`, `Resume`, `Stop`, `SetRate`, `HasVideo`, `UpdateVideo`, `Dispose` (Shutdown). `Reason` turns an HRESULT into one line.
- `FileOperations` (AF-4): `CheckName`, `Lookalike` (the existing name that reads the same as a typed one without being it: composed, case-folded, spaces folded, invisible characters dropped), `CreateFolder`, `CreateFile` (an empty "New file.txt", or "New file - 2.txt"), `Rename` (a change of case included), `DeleteToRecycleBinAsync` (a list of paths, one operation) and `FreeName` ("name - 2.ext", the first name nothing has), `Destinations` (where each source lands: its name, or a free one), `CopyOrMoveAsync` (`SHFileOperationW` with undo allowed, silent, no confirmation, one destination per source with `FOF_MULTIDESTFILES`, each on a single-threaded-apartment thread of its own through `OnShellThreadAsync`, which the window also uses for the Recycle Bin's Restore), `Message` (one line from an exception).
- `Archives` (AF-4.12): `Compress` (entries into a new zip in their folder, named after the one entry or the folder, a folder's tree under its name, an empty folder as an entry, written to a `.tmp` and moved), `Extract` (a zip into a new folder named after it, entry by entry; an entry whose full path would land outside the folder is refused with an `IOException`), `IsZip`; both take an optional progress callback called after each file with the count done and the total (AF-9.3); the names from `FileOperations.FreeName`; .NET's `System.IO.Compression`, no package.
- `OperationHistory`, `Operation` and `OperationKind` (AF-4.14): the window's last twenty operations, newest last (`Push`, `Peek`, `Pop`, `Clear`, `MenuText` "Un&do rename"); an operation is its kind with the paths before and after it (a move into a new folder names the folder), and knows the folder its undo lands in, the entry to select, "notes.md" or "3 items", and its "Undone: …" text. `FileOperations.CheckUndo` (why it cannot be undone now: an entry made or moved is gone, "has changed"; a new folder or file filled, "has files now" / "has content now"; the place to go back to taken, "is already here") and `UndoAsync` (the inverses: a rename back, an empty folder or file deleted, a move back through the shell with the made folder removed when empty, copies, a zip or an extracted folder to the Recycle Bin; a delete is the window's, through the shell's Restore). `RecycleBin` and `RecycleRecord` (AF-4.14): the `$I` record beside a bin item's `$R` file parsed into the original path and the deletion time (version 2 with the path's length, the older fixed field before it); `ReadRecord` from the `$R` path, `Parse` from bytes, tested on synthetic records.
- `Preview` and `PreviewText` (AF-9.4): a file's text for the pane, `Read` (the first megabyte at most, `Cut` beyond it, decoded through `Axit.Core.TextDocument.FromBytes`; null when not text) and `IsText` (the editors' kinds by extension, an empty file, a UTF-16 mark, else no zero byte and under five per cent control characters in the first eight kilobytes).
- `PlayQueue` (AF-9.2, AF-9.3): what the pane's list holds: the queued paths with `Playing` (the index playing or last played, -1 for none; `Set`, `Add`, `Select`, `MoveOn`, `Remove` keeping the index on its file, `Clear`), the operations' status lines (`Report(token, text)`: a new line for -1 or that token's line replaced, the last twenty kept), `Lines(active)` (the names, the playing one marked "(playing)" while the player is active, then the status lines, or "Queue is empty"), `IsFile`, `Information` ("03 Chapter 3.mp3, 3 of 12").
- `UserPrograms` and `UserProgram` (AF-4.11): the user's own programs and scripts of Open with a custom program ▸: `DefaultName` (the file name without its extension), `StartInfo` (a `.ps1` through `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`, anything else through the shell, every entry's path an argument, the first one's folder the working directory).
- `FileSettings` (AF-8.1): the settings file, on the bundle's `WindowSettings`, with the last folder, the recent folders, `ShowHidden`, `ShowDotFiles`, `SayEachFile`, `Speed`, `SeekSeconds`, `Programs` (the user's own, a record each; one without a name or a path is dropped), `Favorites` with `IsFavorite` and `ToggleFavorite` (AF-3.9).

## Gotchas already learned

- In a COM interface a C# `bool` marshals as a two-byte VARIANT_BOOL, not the four-byte BOOL MFPlay uses: the BOOL parameters are `int`.
- MFPlay's events arrive as a pointer to a header, on a thread of MFPlay's choosing (a worker thread was seen); only the header's first two fields (the type and the HRESULT) are read there, and everything else happens on the window's thread through the `post` action the window hands the player (its `BeginInvoke`), so the engine is only ever called from the thread that made it. Calling it from another thread fails with E_NOINTERFACE: Windows has no proxy for MFPlay's interfaces, and `SynchronizationContext.Current` was found not to be the WinForms one in an off-screen probe, which is why the window passes its own marshalling in.
- The `PROPVARIANT` for a position is `VT_I8` with the value in 100-nanosecond units, which is what `TimeSpan.Ticks` are.
- `SHFileOperationW` wants its path list ended by a second null; the marshaller adds one, the code adds the other.
- `Directory.Move` and `File.Move` rename a name whose case alone changes; `Rename` skips the existence check for that case.
