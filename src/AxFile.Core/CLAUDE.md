# AxFile.Core, the pure code

Everything of axFile that needs no window: a folder's entries, the file operations with their undo, the Actions list's lines, the settings. Unit tested in `tests/AxFile.Tests` over temporary folders. The spec is `docs/axfile/SPEC.md` ("SPEC.md" below); the window is `src/AxFile`, with its own `CLAUDE.md`. The bundle rules are in the root `CLAUDE.md`. The player seam and the queue went to `AxMedia.Core` and the text rule to `AxPreview.Core` on 2026-10-22 (`docs/axit/axfile-split.md`); `MediaFiles` and `NaturalOrder` are `Axit.Core`'s since the same day.

## Commands

```
dotnet test tests/AxFile.Tests/AxFile.Tests.csproj
```

## Where things are

- `FolderListing` and `Entry`, `SortBy` (SPEC.md AF-2.2, AF-3, AF-3.8): `Read` (a `Listing`: a folder's entries, hidden and system ones and ones starting with a period left out unless asked and counted, folders first in natural order), `NotShownText` ("Not shown: 3 hidden, 2 starting with a period"), `Sort` (by name, date newest first or size largest first, folders first, ties by name), `Filter` (names containing a text), `Arrange` (both), `SortName` (the type-ahead of AF-3.6 is `Axit.Core/TypeAhead` since 2026-10-24), `EditorOf` (Ctrl+E's editor by extension: axJSON's verb for `.json`, axDown's otherwise), `ListName` ("24 items"; "3 of 24 items, filter chap"), `Information` ("report.pdf, 1.2 MB, modified …"; a drive's free space), `FormatSize`, `Parent` (null at a drive's root), `ThisPC`, `IsThisPC` and `Drives` (the ready drives as folder entries marked `IsDrive`, "Local Disk (C:), drive", AF-3.10), `Resolve` (a typed path with environment variables, a file's path giving its folder and the file).
- `PathCompletion` and `Completion` (AF-3.3, AF-D12): `Split` (a typed text into the folder to list and the start of a name: environment variables expanded, a name or a relative folder in the folder shown, the drives for an empty text, a drive letter or This PC), `Candidates` (the entries starting with it in the list's order, a folder's text ending in a backslash; the drives' roots; empty when the folder cannot be read), `Spoken` ("Windows, folder, 2 of 5").
- `FileOperations` (AF-4): `CheckName`, `Lookalike` (the existing name that reads the same as a typed one without being it: the accents composed through the bundle's `Accents` table, since the program runs without the globalization data, case-folded, spaces folded, invisible characters dropped), `CreateFolder`, `CreateFile` (an empty "New file.txt", or "New file - 2.txt"), `Rename` (a change of case included), `DeleteToRecycleBinAsync` (a list of paths, one operation) and `FreeName` ("name - 2.ext", the first name nothing has), `Destinations` (where each source lands: its name, or a free one, around the `reserved` paths a running operation is still writing, AF-4.5), `CopyOrMoveAsync` (`SHFileOperationW` with undo allowed, silent, no confirmation, one destination per source with `FOF_MULTIDESTFILES`, each on a single-threaded-apartment thread of its own through `OnShellThreadAsync`, which the window also uses for the Recycle Bin's Restore), `CheckUndo` (why an operation cannot be undone now: an entry made or moved is gone, "has changed"; a new folder or file filled, "has files now" / "has content now"; the place to go back to taken, "is already here") and `UndoAsync` (the inverses: a rename back, an empty folder or file deleted, a move back through the shell with the made folder removed when empty, copies, a zip or an extracted folder to the Recycle Bin; a delete is the window's, through the shell's Restore), `Message` (one line from an exception; Windows' sharing violation, HRESULT 0x80070020, becomes `InUse`, "In use by another program: a terminal or an app runs in it, or the file is open", and an `IOException` access denied `AccessDenied`, since both come from outside axFile and the Windows text does not say what to do; the shell's codes 0x20 and 0x21 are the same text).
- `Operation` and `OperationKind` (AF-4.14, AF-9.3): an operation is its kind with the paths before and after it (a move into a new folder names the folder), and knows the folder its undo lands in (`Folder`), the entry to select then (`Select`), where it left its result (`ResultFolder`, `Result`, for Enter on the line), "notes.md" or "3 items" (`What`), its menu label and its "Undone: …" text.
- `ActionLog`, `ActionEntry`, `ActionState`, `ActionKind` and `ActionSection` (AF-9.2, AF-9.3): the Actions list's lines, operations and changes of the marks, shown in three sections under header lines (`Lines`: Running first, then Operations, then Selection, each in time order; `Header`), the last fifty operations kept and the last twenty undoable, the last twenty selection lines kept: `Begin(text, folder)` a running line, `Progress`, `End(entry, text, operation)`, `Fail(entry, reason)`, `Add(text, operation)` a line done at once, `Mark(text, folder, select, before)` a change of the marks with the paths marked before it, `Rewrite` (a range's line as it grows), `DropSelection` (another folder shown), `Newest()` the operation Ctrl+Z in the folder list takes (never a selection line), `Undone`, `NotUndone(entry, reason)`, `EntryAt` and `IndexOf` (a line of the list to its entry and back; a header has none), `Information` ("Operations, 3 of 12, 21:04"; a header, its name), `MenuText` ("Un&do rename"), `Latest` (the newest line of any kind, which Tab lands on), `LatestOperation` (the status bar's text), `Items` ("1 item", "5 items"); an entry's `Line` (with ", undone" or ", not undone: <reason>"), `Section`, `CanUndo` (an operation, or a selection line with its `Before`) and `Location` (where Enter goes: the result, or the undo's landing once undone). The log takes a clock for the tests.
- `Marks` and `MarkChange` (AF-3.7, AF-9.2): the marks on the shown entries and the Shift range being made, one method per key (`Toggle`, `All`, `None`, `ToHere`, `Extend`; `Keep` for a list made again, `Restore` for Ctrl+Z on a selection line, `Clear` for another folder), each returning the rows whose mark flipped, the marks before, the line of the Actions list (null when nothing is recorded), whether a range began, the entry the line leads to, and the words said. The marks are on shown entries only, so that the count said and the entries acted on are one set; the window applies each change (`FileForm.ApplyMarks`).
- `RecycleBin` and `RecycleRecord` (AF-4.14): the `$I` record beside a bin item's `$R` file parsed into the original path and the deletion time (version 2 with the path's length, the older fixed field before it); `ReadRecord` from the `$R` path, `Parse` from bytes, tested on synthetic records.
- `Archives` (AF-4.12): `Compress` (entries into a new zip in their folder, named after the one entry or the folder, a folder's tree under its name, an empty folder as an entry; the zip's name is taken at once with an empty file, so that a second compress running meanwhile picks the next, then the zip is written to a `.tmp` and moved over it, the empty file deleted on a failure), `Extract` (a zip into a new folder named after it, entry by entry; an entry whose full path would land outside the folder is refused with an `IOException`), `IsZip`; both take an optional progress callback called after each file with the count done and the total (AF-9.2); the names from `FileOperations.FreeName`; .NET's `System.IO.Compression`, no package.
- `UserPrograms` and `UserProgram` (AF-4.11): the user's own programs and scripts of Open with ▸: `DefaultName` (the file name without its extension), `StartInfo` (a `.ps1` through `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`, anything else through the shell, every entry's path an argument, the first one's folder the working directory).
- `FileSettings` (AF-8.1): the settings file, on the bundle's `WindowSettings`, with the last folder, the recent folders, `ShowHidden`, `ShowDotFiles`, `SortBy`, `Programs` (the user's own, a record each; one without a name or a path is dropped), `Favorites` with `IsFavorite` and `ToggleFavorite` (AF-3.9); an older file's player keys are ignored.

## Gotchas already learned

- `SHFileOperationW` wants its path list ended by a second null; the marshaller adds one, the code adds the other.
- `Directory.Move` and `File.Move` rename a name whose case alone changes; `Rename` skips the existence check for that case.
- An `ActionEntry` that fell off the front of the log is still the object the window holds for a running operation; the log's `Progress`, `End` and `Fail` change it without looking it up, so nothing breaks when fifty quick operations outrun a slow one.
