# AxFile, the window

The WinForms side of AxFile: one list with a folder's entries, a video area shown only while a video plays, a status bar, the bundle's notices. The pure code (the folder's entries, the media rules, the player seam, the operations, the settings) is `src/AxFile.Core`, with its own `CLAUDE.md`. The spec is `docs/axfile/SPEC.md` ("SPEC.md" below); the guide `docs/axfile/user-guide.md` is embedded by `AxFile.csproj` for Help → User guide; the manual test plan is `docs/axfile/nvda-test-plan.md`. The bundle rules are in the root `CLAUDE.md`.

## Commands

```
.\run-axfile.ps1 C:\Music\Dune    # build Axit and start AxFile on the folder (run.ps1 -App file); a file selects itself in its folder
.\run-axfile.ps1                  # the last folder opened
dotnet build Axit.sln
dotnet test tests/AxFile.Tests/AxFile.Tests.csproj
```

## Where things are

- `AxFileApp`: the entry point `Run` that Axit's `Program` calls (bundle AX-1.7), one call into `Axit.Forms/AppHost.Run` with the one folder or file of the command line, the settings and the window; the log (`axfile.log`), the crash handling, `--help` and `--version` are the host's.
- `FileForm`, in four partial files. `FileForm.cs`: the controls (the list, the rename box as a child of the list, AF-4.2, the video area, the status bar), the menus (AF-6.1; `FillItemMenu` fills the two `ItemMenu`s, the bar's Item drop-down and the list's context menu, AF-4.6), the hooks the window base asks for, `WndProc` (the shell menu's messages forwarded to `Shell`), `ProcessWindowKey` (the one key switch, from `BundleKeys` and `AxFileKeys`; Enter, Backspace, Space, F2, Delete, Ctrl+X, Ctrl+C, Ctrl+V, Ctrl+A and Ctrl+Shift+A only while the list has the focus; Shift+F10 and the Applications key are the list's own and have no case), `Do` (a task with an escaped exception turned into a notice), `Failed` (one line as an announcement, more as a notice). `FileForm.Browse.cs`: `StartAsync`, `ShowFolderAsync` (the read on a task, the list refilled with the selection by name, the title, the recent list; a folder gone gives the notice and the nearest parent that exists), `Rearrange` and `FillList` (`_entries` is the folder as read, `_shown` what the list holds after the filter and the sort order, AF-3.8; every index into the list is into `_shown`; an empty folder, or a filter nothing passes, gets one item, "No items in this folder" or "No names contain x", which `CurrentEntry` does not count as an entry), `SetSort`, `ShowFilterNotice`, `ApplyFilter`, `ClearFilter` (Escape, only while a filter is on), `NoFolderHere` (the guard of a command that needs a real folder: "No folder", or "Choose a drive first" at This PC, AF-3.10; `ShowFolderAsync` reads `FolderListing.Drives` for `FolderListing.ThisPC` and remembers nothing there; `GoUp` goes there from a root, selecting the drive by its path), `FillFavourites` and `ToggleFavourite` (AF-3.9), `SayNoEntry` (the guard every command on an entry announces: no folder, an empty folder, nothing selected), the selection (AF-3.7, AF-D9: `_selected`, the marked paths; `ItemText`, the item with ", selected"; `ToggleSelection`, `SelectAll`, `SelectNone`; `SelectedEntries` and `Targets`, what an operation acts on: the marks, or the current entry), `OpenSelected` (Enter by `FolderListing.WayOf`), `GoUp`, the folder picker, the recent submenu, Go to folder, refresh (F5, and silently on activation when the folder's write time moved), find in the list, information. `FileForm.Operations.cs`: new folder, the rename in place (`Rename`, `OnRenameKey`, `CommitRename`, `CancelRename`, `EndRename`), delete (on the marked entries in one shell operation, `NameAfter` choosing what to select next), copy path, cut, copy and paste through the clipboard (`CopyOrCut`, `Paste`, AF-4.8; cut, copy and copy path take `Targets`), the File Explorer and the other apps' windows (`NewWindow` for Ctrl+N, `OpenIn` on the folder, `OpenInAxit` on the entry, AF-4.9), open in editor, open with Windows (the Open with dialog when Windows has no program), the user's own programs (AF-4.11: `FillPrograms` refills the Open with a custom program ▸ submenu from the settings on each opening, `RunProgram` starts one on `Targets` through `UserPrograms.StartInfo`, `AddProgram` is the file picker then the name notice, `RemoveProgram`), and Windows' own ways with the entry (AF-4.7): `OpenWith`, `ShowProperties`, `ShowWindowsMenu`. `FileForm.Player.cs`: the engine made on first use with the video area's handle, the queue from the folder at the moment of Enter (AF-D6), `PlayCurrent`, the events (`OnStarted`, `OnEnded`, `OnFailed`, `MoveOn`), the transport keys, the speed, Go to time, Ctrl+Q, the status bar's clock, `FitVideo`.
- `AxFileKeys`: the window's keys (SPEC.md AF-6.2; bundle AX-8), the one place a key is changed; `All` feeds the collision test and the F1 text names the same keys.
- `HelpText`: the F1 text and the embedded guide; About is the bundle's.
- `ItemMenu` (SPEC.md AF-4.6, AF-4.10): a `ContextMenuStrip` that takes the Information key in its own `ProcessCmdKey` and calls the window's `SayInformation`, so that Ctrl+I says the entry while the menu is open. Two instances: the list's context menu and the bar's Item drop-down (a `ToolStripMenuItem` takes any `ToolStripDropDown` as its `DropDown`).
- `Shell` (SPEC.md AF-4.7, AF-D8): the three things Windows does with an entry, all on the UI thread: `OpenWith` (`SHOpenWithDialog`), `Properties` (`ShellExecuteExW` with the verb `properties`), `ShowMenu` (the shell's context menu: `SHParseDisplayName`, `SHBindToParent`, `IShellFolder.GetUIObjectOf`, `IContextMenu.QueryContextMenu` into a popup of `CreatePopupMenu`, `TrackPopupMenuEx` with the command returned, `InvokeCommand`), and `ForwardMenuMessage`, which the window's `WndProc` calls so that the shell fills its submenus (`IContextMenu2`/`3.HandleMenuMsg`). The interfaces are declared in vtable order with `PreserveSig`, as `MediaPlayer`'s are.

## Rules

1. Every control gets an `AccessibleName`; the list is named with the folder and its count; nothing speaks on a plain arrow key; a command's result is one announcement (AF-7), on the list, or on the notice while one shows. The player's "Playing <name>" when it moves on by itself is the one unprompted announcement, and a setting.
2. The folder reads and the operations never run on the UI thread: `Task.Run` for the reads, the rename and the new folder, a thread of its own for the shell's delete; the player's events come back on the UI thread through the `BeginInvoke` the window hands `MediaPlayer` at creation.
3. No second window (bundle AX-7.2): questions and errors are notices; the folder picker and File Explorer are the system's own windows; the video area is a panel inside the window.
4. Run the `accessibility-review` skill on a change here before committing, and check it with NVDA following the test plan.

## Gotchas already learned

- Enter in a `ListBox` reaches `ProcessCmdKey` as `Keys.Return`; handled there with a `_list.Focused` check, and returning true keeps the list from dinging. Backspace, Space, F2 and Delete are the same.
- A read that comes back after the user has moved on is dropped (`_reads`): a slow folder would otherwise overwrite a faster one chosen later.
- The video area's handle must exist before the engine is made (`_video.Handle` creates it, hidden or not); the engine needs it at creation and draws nothing in it for a sound file.
- The queue holds paths, not entries: the list may show another folder by the time a file ends.
- An array parameter of a COM interface method marshals as a SAFEARRAY by default (P/Invoke defaults to a C array): `GetUIObjectOf`'s list of item ids is `[MarshalAs(UnmanagedType.LPArray)]`, or the shell reads garbage and the process dies with an access violation, which the probe found.
- A `[ComImport]` interface that derives from another gets no vtable slots from it: `IContextMenu2` and `IContextMenu3` repeat `IContextMenu`'s three methods before their own. A cast of the object to the derived interface is the QueryInterface.
- The shell's menu is tracked after a `BeginInvoke`, so that the Item menu (a `ToolStripDropDown`) has closed and the list has the focus back; `TrackPopupMenuEx` wants its owner in the foreground. A `WM_KEYDOWN` of Down posted just before it selects the first item for the keyboard, as File Explorer's Shift+F10 does; otherwise a native popup opens with nothing selected and NVDA reads nothing until an arrow key.
- The rename box sets its selection before it takes the focus: a `TextBox` that gets the focus selects all its text unless a selection was set first. `EndRename` gives the focus back to the list before hiding the box, or WinForms picks the next control itself; the box's `Leave` cancels a rename, and `CancelRename` is a no-op once `_renaming` is null, so the commit path does not cancel itself.
- The keys of an open `ToolStripDropDown` go to the drop-down's `ProcessCmdKey` through WinForms' menu-mode message filter, never to the form's: a key that should work inside a menu is handled in the menu subclass (`ItemMenu`). The menu's `Click` runs after the drop-down has closed; what needs the focus back on the list (the rename box, the shell's popup) is still posted with `BeginInvoke` to be safe.
- The clipboard's file list is `DataFormats.FileDrop` (`CF_HDROP`); whether File Explorer cut or copied is the four-byte "Preferred DropEffect" format (2 means move), read back as a `MemoryStream`. After a move the clipboard is cleared, as File Explorer does.
- The shell's extensions run in this process while its menu is up; an exception from one is caught and reported, a crash in one is not ours to prevent, which is why the menu is behind one item (AF-D8).
- The selection is marks of the window's own written into the item texts (", selected"), not `SelectionMode.MultiSimple` (AF-D9): the list box's multiple selection separates the caret from the selection, so everything "current" would need `LB_GETCARETINDEX` and `LB_SETCARETINDEX`, and what NVDA says on the toggle was unknown. Setting `_list.Items[i]` to a new text deletes and reinserts the native item and selects it again; whether NVDA reads it a second time after Space is a step of the test plan.
