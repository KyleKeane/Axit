# Axit.Core, the shared pure code

Code every app may use and no window needs (`docs/axit/SPEC.md` AX-6.1): `Dispatch` (which app a command line starts, AX-1; `Apps`, the name and verb of each app, for the Axit menu), `BundleInfo` (the version, read from the executable), `AppPaths` (settings, logs, updates and the recently closed list under the `Axit` folders, AX-5.1), `SettingsFile` (how every app's settings file is read and written, and the take-over of an old file, AX-5.2 and AX-5.3), `WindowPlacement` (the window's place and size, in every app's settings), `Log` (one file per app; each app calls `Log.UseApp` first thing in its `Run`), `Updates/UpdateCheck` (the latest GitHub release: JSON parsing, version comparison; the repository name lives here) and `Updates/Updater` (the download and the hand-over to `install.ps1`, AX-3), `Audio/WaveTone` (the chimes, the ticks and the working music as WAV bytes, generated in code; no media files ship), `Paragraphs` (where Ctrl+Up and Ctrl+Down go in a text with `\r\n` line ends: the starts of its paragraphs, the first line or a line with text after a blank line, for `Axit.Forms.EditParagraphs`). `MarkdownOutline` (docs/axdown/SPEC.md §9): the elements of a Markdown text for navigation keys, outside fenced code blocks: headings with a level filter, links, list items and lists, block quotes and tables, each with `Next…` and `Previous…` from a caret position returning an `Element` with `Start` and `Spoken`; block kinds by line, links by position. It came from AxDown.Core on its second use. `AxitWindows` (docs/axit/SPEC.md AX-9): the window lists of the Axit menu from the windows `Axit.Forms.AxitMenu` reads off the system in Z order, which is recency: the app from a title's ending (" - AxDown"), Open windows without the current window, each app's windows with it, and the item labels with the number as the mnemonic and a full stop as a pause ("&1. notes.md - AxDown"; the apps' recent lists use the same `Label`). `RecentlyClosed` (AX-9.4): the bundle's list of the last ten files and folders the windows held when they closed or swapped them, in `%APPDATA%\Axit\recently-closed.json` through `SettingsFile`: `Remember` from a window, `Load` for the menu (entries whose path still exists), `Title` as "notes.md (C:\notes\notes.md) - AxDown". `BundleAbout` (AX-9.9): the About sections of the bundle, each a notice's title and text: Version (with the window's latest-release state), Licence, Attribution, and the Axit guide, `docs/axit/README.md` embedded by `Axit.Core.csproj` as `AxitGuide.md`. `TextDocument` (docs/axdown/SPEC.md AD-3): a text file as an editor window holds it, with the encoding, the byte order mark and the line ending it came with, so that `ToBytes` writes it back as it was; `FromBytes` and `ToBytes` are the pure core, `Read` and `Write` add the file and the 32 MB limit. `EditorSettings` (AD-8): what an editor window remembers between runs (font, word wrap, recent files, window, the update check), read and written through `SettingsFile` into the app's own file. Both came from AxDown.Core on their second use, AxJSON. Gotchas of `TextDocument`: the Windows code pages come from `CodePagesEncodingProvider`, registered in its static constructor; the system's ANSI page is asked with `GetACP`, since the executable runs with invariant globalization and the culture cannot tell; an answer of 65001 falls back to 1252, since the bytes were just found not to be UTF-8; the encodings are constructed with their marks so that `GetPreamble` knows them; `GetBytes` never writes a mark, `ToBytes` adds it when the file had one.

Unit tested in `tests/Axit.Tests`: `DispatchTests`, `SettingsFileTests`, `UpdateCheckTests`, `WaveToneTests`, `ParagraphsTests`, `MarkdownOutlineTests` and `MarkdownElementsTests` (docs/axdown/SPEC.md §9), `AxitWindowsTests` and `RecentlyClosedTests` (AX-9), `TextDocumentTests` and `EditorSettingsTests` (docs/axdown/SPEC.md AD-3, AD-8), the bundle's own `LayoutTests` (the project references point one way, M2) and `KeyTests` (no window key equals a bundle key, AX-8.4).

Rules: nothing here references an app (M2); a piece arrives here only when a second app needs it, unchanged where possible (M3); plain static classes and records, no frameworks (B-10). An app's settings class stays in the app; only the file handling is shared.
