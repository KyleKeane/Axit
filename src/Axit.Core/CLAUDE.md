# Axit.Core, the shared pure code

Code every app may use and no window needs (`docs/axit/SPEC.md` AX-6.1): `Dispatch` (which app a command line starts, AX-1; `Apps`, the name and verb of each app, for the Axit menu), `BundleInfo` (the version, read from the executable), `AppPaths` (settings, logs, updates and the recently closed list under the `Axit` folders, AX-5.1), `SettingsFile` (how every app's settings file is read and written, and the take-over of an old file, AX-5.2 and AX-5.3), `WindowPlacement` (the window's place and size, in every app's settings), `Log` (one file per app; each app calls `Log.UseApp` first thing in its `Run`), `Updates/UpdateCheck` (the latest GitHub release: JSON parsing, version comparison; the repository name lives here) and `Updates/Updater` (the download and the hand-over to `install.ps1`, AX-3), `Audio/WaveTone` (the chimes, the ticks and the working music as WAV bytes, generated in code; no media files ship), `Paragraphs` (where Ctrl+Up and Ctrl+Down go in a text with `\r\n` line ends: the starts of its paragraphs, the first line or a line with text after a blank line, for `Axit.Forms.EditParagraphs`). `MarkdownOutline` (docs/axdown/SPEC.md §9): the elements of a Markdown text for navigation keys, outside fenced code blocks: headings with a level filter, links, list items and lists, block quotes and tables, each with `Next…` and `Previous…` from a caret position returning an `Element` with `Start` and `Spoken`; block kinds by line, links by position. It came from AxDown.Core on its second use. `AxitWindows` (docs/axit/SPEC.md AX-9): the window lists of the Axit menu from the windows `Axit.Forms.AxitMenu` reads off the system in Z order, which is recency: the app from a title's ending (" - AxDown"), Open windows without the current window, each app's windows with it, and the item labels with the number as the mnemonic and a full stop as a pause ("&1. notes.md - AxDown"; the apps' recent lists use the same `Label`). `RecentlyClosed` (AX-9.4): the bundle's list of the last ten files and folders the windows held when they closed or swapped them, in `%APPDATA%\Axit\recently-closed.json` through `SettingsFile`: `Remember` from a window, `Load` for the menu (entries whose path still exists), `Title` as "notes.md (C:\notes\notes.md) - AxDown". `BundleAbout` (AX-9.9): the About sections of the bundle, each a notice's title and text: Version (with the window's latest-release state), Licence, Attribution, and the Axit guide, `docs/axit/README.md` embedded by `Axit.Core.csproj` as `AxitGuide.md` (read through `EmbeddedText`, which every app's `HelpText.UserGuide` uses for its own guide). `WindowSettings` (AX-6.5): the base of every app's settings class, the font, the update check and the window's place with their sanitising. `TextDocument` (docs/axdown/SPEC.md AD-3): a text file as an editor window holds it, with the encoding, the byte order mark and the line ending it came with, so that `ToBytes` writes it back as it was; `FromBytes` and `ToBytes` are the pure core, `Read` and `Write` add the file and the 32 MB limit. `EditorSettings` (AD-8): what an editor window remembers between runs (font, word wrap, recent files, window, the update check), read and written through `SettingsFile` into the app's own file. Both came from AxDown.Core on their second use, AxJSON. `EditHistory` and `EditStep` (AD-2.5, 2026-10-21): the editor shell's undo and redo history: `Diff` finds the one step between the text before and after a change by the common prefix and suffix, the caret settling an ambiguous place ("a" typed next to an "a"); `Record` merges a change into the open run when its key was typed at `RunCaret` (more typing, a Backspace at the run's end, a Delete at its caret) and makes any other change (`typedAt` -1: a paste, a cut, a command, a reload) a step of its own that closes the run; `Break` is the window's second of silence; `Undo` and `Redo` hand the step back for the window to apply through the selection; four million characters of deltas at most, the oldest dropped. Gotchas of `TextDocument`: the Windows code pages come from `CodePagesEncodingProvider`, registered in its static constructor; the system's ANSI page is asked with `GetACP`, since the executable runs with invariant globalization and the culture cannot tell; an answer of 65001 falls back to 1252, since the bytes were just found not to be UTF-8; the encodings are constructed with their marks so that `GetPreamble` knows them; `GetBytes` never writes a mark, `ToBytes` adds it when the file had one. The console-to-transcript pieces came from AxClaude.Core on their second use, AxTerminal (2026-10-18; docs/axterminal/SPEC.md §5, AT-D6): `Pty/PtyHost` (ConPTY through P/Invoke, the one implementation; `tools/PtyCapture` records through it) and `Pty/StreamRecorder` (the raw stream to a `.vt` file plus chunk index); `Vt/VtParser` (byte stream to print, control, CSI and OSC, written into the `Screen` it is given), `Vt/Screen` (cells, cursor, scroll region; rows carry their transcript `Line`; `PullRowText` at a frame's end; events for the frame end, the bell, the title, the cursor homed) and `Vt/Wcwidth`; `Transcript/Line` and `LineKind` (one logical line with its kind, heading level, join flag and hidden flags; the Claude-specific kinds and the echo, replay and repaint flags stay here because the class moved whole), `Transcript/LineStore` (the lines and what a screen does to them, create, commit, remove, the text of a rewritten row; each app's model derives from it: AxClaude's `SessionModel`, AxTerminal's model), `Transcript/TranscriptMirror` (visible lines to edit-control edits, the caret's place afterwards, display line numbers, the find search, the reading breaks; `ShowMarkers` off shows heading lines as `Line.BareText`, without the `#`, the export unchanged) and `Transcript/Utterance` (how spoken lines join into one notification). Their tests stayed in `tests/AxClaude.Tests`, where the recorded fixtures drive them; the gotchas are in `src/AxClaude.Core/CLAUDE.md`. `MediaFiles` (docs/axmedia/SPEC.md AM-4): the rules of sound and video files that need no engine, the extension sets with `IsMedia`, the time format and the typed time, the speed steps; from AxFile.Core on its second use, AxMedia (2026-10-22), since AxFile keeps asking which entries are media. `NaturalOrder`: `StrCmpLogicalW` of shlwapi as an `IComparer<string>`, File Explorer's order of names (2 before 10); from AxFile.Core the same day, since AxMedia orders a folder's files as AxFile does. `TextMatch` (AX-10.3): whether a name holds every word of a typed text, case and accents folded away (`Fold`, `Words`), and its `Rank` by the first word (the name starts with it, a word does, anywhere), null when a word is missing; from AxStart.Core's `ProgramMatch` on its second use, the command palette (2026-10-22).

Unit tested in `tests/Axit.Tests`: `DispatchTests`, `SettingsFileTests`, `UpdateCheckTests`, `WaveToneTests`, `ParagraphsTests`, `MarkdownOutlineTests` and `MarkdownElementsTests` (docs/axdown/SPEC.md §9), `AxitWindowsTests` and `RecentlyClosedTests` (AX-9), `TextDocumentTests`, `EditorSettingsTests` and `EditHistoryTests` (docs/axdown/SPEC.md AD-3, AD-8, AD-2.5), `MediaFilesTests` (docs/axmedia/SPEC.md AM-4), `TextMatchTests` (AX-10.3), the bundle's own `LayoutTests` (the project references point one way, M2) and `KeyTests` (no window key equals a bundle key, AX-8.4).

Rules: nothing here references an app (M2); a piece arrives here only when a second app needs it, unchanged where possible (M3); plain static classes and records, no frameworks (B-10). An app's settings class stays in the app; only the file handling is shared.
