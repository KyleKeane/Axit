# Axit

Axit is a bundle of accessible Windows apps for a blind developer who uses the NVDA screen reader, shipped as one self-contained executable. Its apps are **axClaude**, a front end for the Claude Code CLI (`claude --ax-screen-reader` in a ConPTY pseudo console, shown as a line-by-line transcript), **axDown**, a barebones editor for Markdown and text files, **axJSON**, the same editor for JSON files with JSON's navigation keys and a Format command (the two editors are one shared window, the text editor shell in `Axit.Forms`, each app being a record of what differs), **axGIT**, a git manager for one repository, reached from the other windows on the repository of the folder or file in hand, **axTerminal**, a shell as a transcript in axClaude's kind of window, **axFile**, a file manager for one folder with an Actions list of every operation to undo or walk back to, **axMedia**, a player for sound and video files with one queue, and **axPreview**, a read-only viewer for one text file (the editor shell in a read-only mode); the last two came out of axFile on 2026-10-22 (`docs/axit/axfile-split.md`), each with a hand-over from a starting process to its open window (`Axit.Forms/AppMessage`); and **axStart**, a program launcher, a background process from sign-in whose global hotkey shows one search field over the Start menu's programs (2026-10-22, released in 3.4.0; its NVDA pass is still to come); and **axCalc**, a calculator as one expression field and a history list (2026-10-23, on the branch `axcalc`, not yet heard under NVDA). `docs/axit/plan.md` records how the repository became the bundle (2026-10-02) and what is still to come: its "Still to come" section is the one list of apps asked for or suggested and not built yet (AxList and AxTask, the list and to-do managers, among them), where a new idea for an app is recorded. Releases go from `main`; larger work runs on a branch and merges when it has passed its NVDA checks.

Specifications are the source of truth: `docs/axit/SPEC.md` for the bundle (launch, install, update, release, shared pieces, the accessibility rules, the modularity rules), `docs/axclaude/SPEC.md` for axClaude, `docs/axdown/SPEC.md` for axDown, `docs/axjson/SPEC.md` for axJSON. A behaviour change updates the spec in the same commit.

## Stack and constraints

- .NET 10 (LTS), C#, WinForms. WinForms is deliberate: native Win32 controls (EDIT, menus, status bar, ListBox) that NVDA reads reliably. No WPF, Avalonia or web view.
- Zero third-party runtime dependencies, no NuGet packages. Windows APIs are called through P/Invoke.
- Plain code (SPEC B-10): plain classes, static methods, records for data, one obvious way to do each thing. No dependency injection, no interfaces with one implementation, no reflection beyond what WinForms needs, no clever generics. A smaller model must be able to change one app with only that app's folders, spec and notes in context.
- Everything that does not need a window lives in a `.Core` project and is unit tested; recorded fixtures live under `tests/fixtures`.

## Commands

`dotnet build Axit.sln`; `test.ps1 [<App>]` runs every test project (or one) in Release, one by one, as the workflows do, and is what `release.ps1` and `run.ps1 -Test` call: run it before a commit (never `dotnet test Axit.sln` while Axit runs, which writes into its `bin\Debug`; and Debug alone misses what Release treats as errors, which cost 3.3.0); `run.ps1 [-App claude|down|json|git|terminal|file|media|preview|start|calc] [<path>]` builds `src/Axit` and starts one app (axClaude on a folder by default; `-New`, `-NoBuild`, `-Test`), and `run-axclaude.ps1`, `run-axdown.ps1`, `run-axjson.ps1`, `run-axgit.ps1`, `run-axterminal.ps1`, `run-axfile.ps1`, `run-axmedia.ps1`, `run-axpreview.ps1`, `run-axstart.ps1` and `run-axcalc.ps1` are the same with `-App` filled in; `Axit.exe <verb> …`, or a folder or file alone, picks the app. Each app's own commands are in its `CLAUDE.md`. Bundle-level scripts: `publish.ps1` (self-contained exe + installer + guide into `publish\`, zip, install for this user; `-NoInstall`), `install.ps1` and `install.cmd` (per-user install, `-Uninstall`), `release.ps1 <version>` (after a `## <version>` section in `CHANGELOG.md`: tests, version, commit, tag, push; GitHub Actions publishes the release the apps update from), `gh run watch`, `tools/make-icon.ps1`, `tools/AxitDrive <script>` and `tools/QaRun` (the automated checks, `docs/axit/automation.md`: windows driven on a desktop of their own and Claude sessions without windows, always with `--model haiku`), `manual_tests/prepare.ps1 [<app>]` (makes and resets the files of the NVDA test passes in `manual_tests/<app>`, spoken WAV files and a scratch git repository among them; git ignores all but the script and the `_main.md` files, so a file a test pass needs is added to the script, never committed).

## Rules of the bundle

1. Accessibility first (SPEC AX-7). Every control gets an `AccessibleName`; every action works without a mouse; the caret moves only on the user's own command; results of navigation are announced through one UI Automation notification.
2. No second window of an app's own (AX-7.2): questions, errors and help texts are notices inside the window (`OverlayPanel`), what an app waits on goes in place of its input field (`ControlArea`); never a `Form` or a `MessageBox` once a window exists. The Windows folder, file and font pickers, and the shell's own dialogs and menu an app hands an entry to (axFile's Open with, Properties and Windows menu), are the only separate windows. An app that keeps one window (axMedia, axPreview) takes what a second start brings through `AppMessage`, a window message, and the second process ends.
3. Never block the UI thread on I/O; background reads are marshalled to the UI thread and batched.
4. Modularity (SPEC 5.3): one app, one set of folders; references point one way (an app never references another app; shared projects never reference an app; `LayoutTests` enforces it); shared code moves on the second use, unchanged, one piece per commit; notes next to the code; one version, one changelog with app prefixes (`axClaude:`, `axDown:`, `Axit:`). A new app follows `docs/axit/adding-an-app.md`.
5. Keys (SPEC AX-8): every key is either bundle-wide (`Axit.Forms/BundleKeys`, the same in every window) or window-specific (one table per window); a key is changed in its table and nowhere else; a test fails on a collision.
6. Personal data never enters the repository or a session's output: only the licence identity (Dr. Kyle Keane, www.kylekeane.com) appears; `PrivacyTests` fails on an e-mail address or an account path; recordings are read through PtyCapture's redacting `--dump`, never `--raw`, `cat` or `type`.
7. Git hygiene: small commits with imperative subject lines; never commit `bin/`, `obj/`, ad-hoc captures or `.claude/settings.local.json`. Every commit builds and passes the tests; `main` is always releasable. Fetch before building on the repository: `git fetch origin` at the start of a session and before its first commit, and bring in anything `origin/main` has gained (`git pull --ff-only` on `main`, a merge or rebase on a branch) before new work stacks on a stale base. `release.ps1` fetches and refuses a `main` that is behind `origin/main`; git itself only rejects the push, after local commits have piled up.
8. Local first (SPEC G6, B-15): every app except axClaude keeps its full utility with the network off; the update check is the only network call a window makes on its own, and it is a setting; AI help is one shared, optional service that no app's feature depends on, never a feature built into one app.

## Environment gotchas (bundle-wide)

- A running app locks its `bin` folder. Build somewhere else to check a change (`dotnet build <project> -o <scratch dir>`) and ask the user to restart the app for a real run. Dialogs and menus can be checked off screen from a small probe project that references the scratch build; never activate windows or send keys while the user is working. A probe started from this session is a child of the user's foreground app and may take the foreground, so a probe is a `WinExe` (no console window) that writes its output to a file, shows its own forms with `ShowWithoutActivation` and the app's windows with `ShowWindow(SW_SHOWNOACTIVATE)`, `SetActiveWindow` (the thread's own active window, so that controls can take the focus) and `OnShown` by reflection, never calls `Show()`, `Activate()` or `SetForegroundWindow`, plays silent media, and checks `GetForegroundWindow()` right before and right after showing (the user lost the keyboard to probe windows on 2026-10-21). Verified for axFile's window: the foreground stays. Not for axClaude's: `SetActiveWindow` on `MainForm` made it the foreground window in the probe process, cause not yet found, so a probe of axClaude's window is not run while the user works until it is. Menu mode of a menu bar cannot be driven this way at all: WinForms enters it only in the foreground window.
- The Bash tool mangles backslashes inside heredocs: use the Write tool for source files. A PowerShell one-liner sent through the Bash tool loses its backticks to command substitution; `-replace` is case-insensitive, so a mangled pattern once turned every capital N of a file into n. Run PowerShell through the PowerShell tool.
- Windows PowerShell 5.1: `$PSScriptRoot` is empty while parameter defaults are evaluated, and a function that returns a byte array unrolls it unless written `return , $bytes`.

## Manual verification

Any change to focus handling, key handling, announcements or an edit control is checked with NVDA running, following the app's test plan (`docs/<app>/nvda-test-plan.md`) on the files of `manual_tests/<app>`. Every pass is written down in `docs/axit/nvda-test-record.md`, by step, with the version and the commit, newest first: when a bug comes up, it says when its step last passed.
