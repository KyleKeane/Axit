# Accessibility review

Read the diff of the change (git diff, or the files named by the user) and check every point below. Report each finding with file and line, and say plainly when a point cannot be verified without running NVDA. Do not rewrite the code unless asked.

1. **Names and roles.** Every new control sets `AccessibleName`; a form sets `AccessibleRole.Window` so that NVDA speaks it when it opens. Menu items have a mnemonic (`&`) and either `ShortcutKeys` or `ShortcutKeyDisplayString`. The status labels have no `AccessibleName` and no `Spring` (docs/axclaude/SPEC.md §6.2). No control relies on a visual label alone. For state NVDA already reports (a progress bar, a list position, a check box), the native control is used and the app stays silent.
2. **Caret discipline.** Nothing moves a text control's caret or selection except a user command (AxClaude: the quick keys, find, Backspace, the page keys; AxDown: find, go to line, the heading keys). In AxClaude, output goes through `TranscriptMirror.Update` and the caret is restored with `MapPosition`; while the view has the focus, output waits 250 ms after a key press and for as long as text is selected (`TranscriptView.Sync`). `EM_SCROLLCARET` is sent only on user navigation or while the view has no focus. In AxDown, a save, a reload or a word wrap change leaves the caret where it was.
3. **Announcements.** Everything spoken goes through the form's `Announce`: one UI Automation notification on the main control, or on the notice while one shows. Anything spoken per line is joined into one notification per frame (AxClaude's `Arrivals`, D32). Nothing speaks on a plain arrow key; information comes on demand (AxClaude D26, AxDown G4). The texts match the app's specification word for word (AxClaude §6.4, AxDown AD-7).
4. **No second window.** Questions, errors and help texts go through the form's `ShowNotice` (`OverlayPanel`), what the app waits on goes to `ControlArea`, never a `Form` or a `MessageBox` once a window exists (AX-7.2). A new notice names its default and cancel buttons so that Enter and Escape reach them.
5. **Keys.** Every key comes from `BundleKeys` or the window's table (`AxClaudeKeys`, `AxDownKeys`) and is handled in one place (AX-8); the collision test passes. AxClaude's quick keys act only when the conversation has the focus and only without Ctrl or Alt; Ctrl+C with a selection stays copy; plain Escape in the message field is a guard that only speaks (D20); Shift+Escape is the interrupt; Ctrl+O is never sent (D14). In AxDown, Ctrl+H, Ctrl+I, Ctrl+J and Ctrl+M never reach the edit control as characters (AD-5.1). Handled keys set `SuppressKeyPress`. NVDA's own key combinations are never intercepted, and no global keyboard hook is installed.
6. **Threading.** No I/O on the UI thread that can block: AxClaude's pseudo console is read on a background thread and posted with `BeginInvoke`; downloads and the installer run through `await`, with progress marshalled by `Progress<T>`.
7. **Text view invariants (AxClaude).** `\r\n` between lines and a space before a joined row (`TranscriptMirror.SeparatorBefore`); hidden lines leave the view but stay in the model; `MaxLength = 0`; edits go through `Select` and `SelectedText`, never `Text = …`; a frame that changes nothing visible allocates nothing (D24).
8. **Spec alignment.** Behaviour matches the app's specification. If it intentionally differs, the spec, the user guide and the F1 text in the app's `HelpText` change in the same commit.
9. **Test plan.** State which sections of the app's `nvda-test-plan.md` the change affects and must be rerun.
