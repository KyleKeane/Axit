# NVDA manual test plan

The files for this plan are in `manual_tests/axclaude`, made and reset by `.\manual_tests\prepare.ps1 axclaude`; its `_main.md` says which folder or file each section uses.

Start NVDA before the app. Use the default NVDA settings unless a step says otherwise. Note the app build, the Claude Code version (`claude --version`) and the NVDA version at the top of each run.

Each step says what to do and what NVDA must say or do. A step fails if NVDA says nothing, says the wrong thing, or the caret ends up somewhere else.

## 1. Startup and focus

1. Start the app on a folder that has never been used with Claude. NVDA reads the window title (`<folder> (<full path>) - AxClaude`), then "Message to Claude edit multi line", and no description.
2. Ctrl+Tab: "Conversation read only edit multi line", then the current line.
3. Ctrl+Tab again: the message field.
4. F6 twice, then Ctrl+Shift+Tab twice: as steps 2 and 3.
4a. Ctrl+2: as step 2. Ctrl+2 again: "Conversation" only, the caret does not move. Ctrl+1: the message field. Ctrl+1 again: "Message to Claude". Ctrl+3: the newest "# Output" line, focus in the conversation ("No response yet" before the first reply). Navigate menu, Conversation while the conversation has the focus: NVDA reads the conversation control again, because the menu gives the focus back.
5. Tab from the message field: the conversation. Tab again: the message field. Shift+Tab: the conversation, Shift+Tab again: the message field. The same with a question's list in the field's place, and never a hidden control.
6. Alt: the menu bar opens; Left and Right move across Session, Claude, Navigate, Options, Axit, Help; each item reads its name, mnemonic and shortcut. In Options, Right Arrow opens Sounds, Speech, When Claude is done, Questions, Text, General and Developer as submenus, and nothing stands outside them; in every menu a mnemonic letter chooses one item at once, never cycling between two. Escape closes it. In Navigate, Message field reads "Ctrl+1", a pause, then "1 of 9", never "Ctrl+11 of 9"; the same for Conversation and Latest response.
7. NVDA+End: the status bar, "Claude: ready | manual mode on" (or the current state) followed by the project path. Never "No status bar found", whether the window is maximized, sized to the work area or small. Later, once Claude has named the session (the name follows the mode), make the window narrow and press NVDA+End: the state, the mode, the session name and the full path are all read, even though the path is cut short on screen.

## 2. Dialogs and plain conversation

1. With Options, Questions, "Answer from a list" off for steps 1 and 2 (section 12 step 1 covers the same start at the defaults), and focus in the conversation, read the trust prompt with Down Arrow: "Permission Required: Accessing workspace", the folder path, the `y.` and `n.` options and "Enter y/n:".
2. Ctrl+Tab, type `y`, Enter: "Sent". Within a few seconds: "Done" or "Claude asks" (a second startup dialog may follow; answer it).
3. Type `What is 2+2?`, Shift+Enter, `Answer in one line.` NVDA reads the new line as you type. Enter: "Sent" with a short low note; the field empties and keeps the focus. Then "Responding" with a rising chime, then "Done" with three falling notes.
4. Ctrl+Tab, Shift+O: "# Output 1 Reply from Claude". Down Arrow: a blank line, then Claude's reply. Up Arrow from the marker: a blank line, "Answer in one line.", "What is 2+2?", "# Input 1". No line starts with "you:".
5. `i`: "No next input". Shift+I: "Input 1 heading level 1".
6. Ctrl+Tab. Up and Down in the empty field: NVDA says "blank", nothing is put into the field and AxClaude says nothing.
7. Page keys in the field. With one line typed: Page Down and Page Up read that line again, nothing else happens. Type five short lines, Ctrl+Home: Page Down reads the fourth line, then the fifth, then the fifth again; Page Up reads the third, then the first, then the first again. End reads nothing new and Home returns to the start of the line; Ctrl+End puts the caret after the fifth line and Ctrl+Home before the first. The app says nothing for any of these. Ctrl+A, Delete.
7a. Paragraph keys in the field. Type `one`, Shift+Enter twice, `two`, Shift+Enter, `three`, Shift+Enter twice, `four`: three paragraphs, the second of two lines. Ctrl+Home, then Ctrl+Down reads "two", then "four", then "four" again as the caret reaches the end of the message. Ctrl+Up reads "four" (its start), then "two", then "one", then "one" again. End, then Ctrl+Shift+Up: NVDA says "selected" with "four"; Ctrl+Shift+Down: "unselected four". The app says nothing. Ctrl+A, Delete.

8. F1: in the shortcuts text, Page Down moves a screen of lines and Page Up back; Ctrl+Down reads the next section's heading line ("## Message field", "## Conversation"), Ctrl+Up the one before; Escape closes the notice.

## 3. Reading while output arrives

1. Ask for a long answer ("Write 40 numbered lines"). Ctrl+Tab at once and read the header lines with Up and Down while Claude streams.
2. The caret never moves on its own; NVDA never starts speaking incoming lines; Down Arrow continues from where you were.
3. After "Done", Ctrl+3: "# Output 2 Reply from Claude", focus in the conversation. Ctrl+1, then Ctrl+3 again: the same line. Down Arrow: the blank line, then the first reply line.
4. Ask for one long paragraph ("Write one paragraph of 300 words with no line breaks") and Ctrl+2 at once. Press Down until you reach the line Claude is still writing, then keep pressing Down every second or two while it grows. Each press reads only text you have not heard yet, starting with a whole word; when nothing new has arrived, NVDA re-reads the last row. `l` on any of those pieces: the same line number. After "Done", press Up to the paragraph's first row, then Down through it: it reads in screen rows, and once you have moved to another line and back, Enter copies it as one line and Ctrl+S saves it as one line.
5. Selection: on a reply line, Shift+Down twice: "selected" and the text of each row. Ctrl+C: "Copied"; Ctrl+1 and Ctrl+V in the message field: the two rows. Ctrl+2, Escape: "Selection cleared", and Down reads the row after the one the selection started on; Escape again: the message field. Ask for a long answer, Ctrl+2 at once and select a row with Shift+Down while Claude writes: the selected text stays as it is (Shift+Down again extends it by the next row, never by changed text) until a plain arrow key, after which `l` shows that the conversation has grown. Ctrl+Shift+End, then Down: "unselected" and the last row; the conversation is usable as before.

## 4. Headings and quick keys

1. Ask for a markdown answer with two `##` headings and a bulleted list.
2. Ctrl+Home, then `h` repeatedly: the "# Input" and "# Output" line of each exchange, spoken without the hash and followed by "heading level 1", and Claude's headings followed by "heading level 2", in order. Shift+H goes back. `1`: only the markers.
3. `2`: only Claude's level 2 headings. `3`: "No next heading level 3". Options → Text → Markers in the text off: `h` still says "Input 1 heading level 1", Up and Down read "Input 1" without the hash, the caret stays on its line, and an exported conversation keeps `# Input 1`; on again.
4. `p`: the first line of the next paragraph (a line with text after a blank line, or a `claude:` line), read out; Shift+P goes back. Past the last one: "No next paragraph". After a turn with several tool calls, `o` to its output marker and then `p` repeatedly: each of Claude's short messages between the tool calls is a stop, although no blank line sits in front of it, then each paragraph of the final reply; the tool lines and their output are not stops, even after a blank line, and Ctrl+Alt+P from the output marker reads the same stops without them.
5. `o` / Shift+O, `r` / Shift+R (the same lines as `o`), `i` / Shift+I, `c`, `t`, `e`, `d`, `s`: each announcement matches SPEC.md §6.4.
6. Escape in the conversation: the message field has the focus and nothing was sent (the status still says "ready").
7. Ask for a reply longer than the window ("Write 60 numbered lines"). After "Done", Ctrl+Tab: the newest line. Page Up: a line about one screen higher, once per press, up to the first line, which then repeats. Page Down: one screen at a time down to the last line, which then repeats. The app says nothing itself; NVDA reads each line once.
7a. On the same reply, `o`: its output marker. Ctrl+Down: the first reply line, which follows the blank line under the marker. The numbered lines have no blank line between them, so the next Ctrl+Down goes past all of them to the next "# Output" marker, or to the end of the conversation when there is none, where NVDA reads the last line again. Ctrl+Up: back to the first reply line, then to the output marker, then to the paragraph before it. On the markdown answer of section 4 step 4 (two headings and a list), Ctrl+Down stops where `p` stops: each heading, each paragraph, the list. Ctrl+Shift+Down: NVDA reports the text selected; Ctrl+Shift+Up: unselected; Escape: "Selection cleared". Ctrl+Up and Ctrl+Down are not jumps: Backspace afterwards goes back to the line before the last quick key, not to where Ctrl+Down started.
8. `l`: "Line 37 of 120" or similar. Ctrl+Home, `l`: "Line 1 of 120". Ctrl+End, `l`: the last number equals the total. Arrow keys read only the text, never a number.
9. Ask for one paragraph of about 400 words with no line breaks. Read it: it is one line (Down Arrow from its start goes to the next paragraph or the done line, and `l` before and after differ by one), not fragments that end mid-sentence.
10. Ctrl+F: the Find notice takes the place of the conversation, in the same window: "Text to find edit" and no new window title; Shift+Tab reaches its text, "Enter: Find next. Escape: Cancel." Type a word from the paragraph, Enter: the notice closes, focus is in the conversation, NVDA says the line with the word. F3: the next line with the word, or the same line with "From the top" in front when it is the only one. Shift+F3 goes backwards ("From the end" after a wrap). Ctrl+F: the field holds the previous word, selected; type `zzqqx`, Enter: "Not found: zzqqx" and the caret stays. Ctrl+F, delete the text, Enter: "Type the text to find" and the field keeps the focus; Tab: "Find next button", Tab: "Cancel button", Tab: the field again, nothing else. Alt: the menu does not open. Escape: the notice closes and the focus returns to where it was. F3 in the message field works too and moves the focus to the conversation.
11. On a reply line press Enter: "Line 12 copied" (the number `l` reports), then NVDA reads the message field, focus is there, and Up Arrow reads `_ start of comment on the copied line _`, above it the text on its own line, `Line 12 of 120:` and `_ start of copied line from conversation history _`. Down Arrow back to the empty last line, type a comment, Enter: Claude answers about the quoted line. Ctrl+2: the conversation caret is still on the line you copied. Enter on the long paragraph from step 9: the whole paragraph is copied as one line.
12. Ctrl+Home, `h` three times, `p` twice: Backspace reads "Back to" and the line before the last `p`; four more Backspace presses walk back to the first line; one more: "Nothing to go back to". Page Down, Backspace: back to the line before the page. Enter on two more lines with text already in the field: each block is separated from the text above by one blank line. Send it: the message appears in full between "# Input n" and "# Output n Reply from Claude", with its blank lines and marker lines, and no "you:" row anywhere.
13. On a reply line press `m`: "Bookmark 1 added"; the caret stays (Up Arrow reads "Bookmark 1", Down Arrow the line again). On a reply line further down, `m`: "Bookmark 2 added". Ctrl+Home, `k`: "Bookmark 1, " followed by the first bookmarked line; `k`: "Bookmark 2, " and the second; `k`: "No next bookmark". Shift+K: "Bookmark 1, …" again; Down Arrow reads the bookmarked line; `m` there: "Bookmark 1 removed", and Up Arrow now reads the line that was above the bookmark. `k`, then `m` on the "Bookmark 2" line itself: "Bookmark 2 removed". On the long paragraph from step 9, `m`, then Up Arrow: "Bookmark 3" sits above the whole paragraph, and Down Arrow reads it as one line still. Ctrl+Tab to the message field, Ctrl+Shift+K: the focus moves to the conversation and "Bookmark 4 added" is said for the line the caret was on. Navigate menu: Bookmark this line, Next bookmark and Previous bookmark do the same as `m`, `k` and Shift+K. Ctrl+S: the saved file holds the "Bookmark" lines in place.
14. Ctrl+3, then Ctrl+Alt+P: the paragraphs of the newest reply, from the "# Output" line to the end, in one piece with a pause between them, long paragraphs whole and a bulleted list entire, not its first item alone; the caret has not moved (Down Arrow reads the blank line under the marker). Ctrl+Alt+H: its headings, each with its level. Ctrl+1, then Ctrl+Alt+C: the "claude:" lines from the caret's conversation line on, the focus still in the field. Ctrl+Alt+K: each bookmark with the line it marks. Ctrl+End, Ctrl+Alt+P: "No next paragraph". Ctrl+Home, Ctrl+Alt+P, then Control: NVDA stops at once. Ctrl+Alt+O: the "# Output" lines from the caret's line on, "# Output 1 Reply from Claude heading level 1" and so on. Ctrl+Alt+L and Ctrl+Alt+M: nothing.
15. Ctrl+End, then Shift+I: the last "# Input" line; Shift+H: the last heading. Ctrl+Shift+S, Ctrl+Shift+C, Ctrl+Shift+K and Ctrl+Shift+R still do their own jobs (Send queued messages now, Send Ctrl+C, Bookmark this line, Force Claude to restart); Ctrl+Shift+O: nothing; Ctrl+Shift+P: the command palette (bundle AX-10).

## 5. Permission mode, prompts and interruption

1. In the message field, Ctrl+Shift+M: focus stays, NVDA says the new mode ("manual mode on" or similar), NVDA+End shows the same. Ctrl+Shift+M until the mode you started with comes back.
2. With Options, Questions, "Answer from a list" off (section 12 covers it on), ask Claude to create a file. If a permission prompt appears: "Claude asks". Ctrl+2, Ctrl+End, then Up Arrow to the "Permission Required:" line; Down Arrow: the numbered options and "Enter selection".
3. Type `1`, Enter: "Sent", then "Done" when the tool finishes.
4. Ctrl+O once, on an idle prompt and again while Claude works: "Ctrl+O is off. For tool output, start with --verbose" Each time the conversation does not change (`l` gives the same count before and after), the status stays as it was and nothing else is spoken.
5. Ask for something slow, then Escape in the message field while the status says "working": "Shift+Escape interrupts" and the status still says "working". Shift+Escape: the conversation gains Claude's interruption line and the status is "ready".
6. Claude menu, Send key, Ctrl+C, and Ctrl+Shift+C from the message field: the same as Shift+Escape.
7. With the same option off, type `/model`, Enter: "Claude asks" and, in the conversation, the numbered menu ending in a "Select with numbers" line. Claude menu, Send key, Down, then Up: the "(selected)" mark moves to another entry and back in the redrawn menu. Shift+Escape closes the menu without a change.

## 6. Sending while Claude works

1. Ask Claude to run `sleep 20` with the Bash tool and then reply OK DONE. While the status says "working", type a second message and Enter: "Queued". NVDA+End: "1 message waiting". Ctrl+Tab, Shift+I: only "# Input 1" exists; the second message is not in the conversation yet. Ctrl+Tab back: the field is empty, and Up puts nothing into it.
2. Wait for "Done". In the conversation, Shift+I: "# Input 2". Down Arrow: the second message, a blank line, "# Output 2 Reply from Claude", a blank line, then the part of the reply that answers it. Shift+I again: "# Input 1". No line starts with "you:" or "ctrl+x ctrl+s".
3. Again with a `sleep 20`: send a second message, then Ctrl+Shift+S: "Sending now", and within a few seconds "# Input 2" is in the conversation while the status still says "working". Ctrl+Shift+S with nothing waiting: "Nothing queued" and nothing else happens.

## 7. Project folder

1. Session menu (Alt+S), Show current folder in, File Explorer reads "Ctrl+W"; Enter on it: a File Explorer window opens on the folder and NVDA reads its title. Alt+F4 closes it and the focus is back in AxClaude. Ctrl+W from the message field and from the conversation does the same. AxClaude says nothing for it.
2. Session menu, Open folder opens the standard folder picker; NVDA reads its title and controls; type a path and choose Select Folder.
3. "Folder <name>"; the conversation is emptied: Ctrl+Home reads the "System:" line as the first line, and under it comes only what Claude prints in the new folder, its earlier exchanges under their "from previous session" headings when it has any; the title and the status bar change, and the trust prompt for the new folder appears if needed. Send a message: "# Input 1".
4. Session menu, Open recent folder lists the previous folder as "1. <name> (<path>)", the same shape as the Axit menu's items; choosing it switches back, again with an emptied conversation and that folder's replay under the "System:" line.
5. Ctrl+N (Session menu, New session, its first item): NVDA reads "New session read only edit multi line" and the first line "Folder: <path>". Down Arrow: the line about Enter and Escape. Tab: "Choose folder... button"; Enter opens the picker; Escape closes it and the focus is back on the button. Tab: "How Claude starts grouping, Continue the last conversation radio button checked, 2 of 6". Down Arrow moves through the choices and checks each one; on "Custom" Tab lands on "Custom arguments edit multi line". Type `--continue`, Shift+Enter (a new line), `--name demo`, then Enter: the notice closes, "New session in <name>", and the conversation is cleared: Ctrl+Home reads "System: New session in <path> with --continue --name demo" as the first line, NVDA+End says "Claude: starting" until "Ready", and under the system line Claude's replay of the last conversation arrives with its "from previous session" headings (ticks for its lines). Send a message: "# Input 1". Ctrl+N again: Custom is selected and the field holds `--continue --name demo` on one line. Escape: the notice closes, the focus is back in the message field and Claude keeps running. Ctrl+Shift+R: "Restarting" and the same conversation comes back, so Restart kept the arguments.
6. Ctrl+N, Tab to Choose folder, pick another folder: "Folder: <the new path>" is spoken and the first line of the text now reads it. Up Arrow in the group to "New conversation", Enter: Claude starts fresh in the new folder, the title and the status bar show it, the conversation holds only the system line, which says "with no extra arguments", and what the new Claude prints.
7. Session menu, Open folder, pick an empty folder: Claude's trust question, answer `y`; then "Nothing to continue, new conversation", the conversation shows Claude's "No conversation found to continue" line and the system line, and Claude comes up ready. Send a message: "# Input 1".
8. In a folder with two earlier exchanges, start the app: "Ready", then Ctrl+Home and `i`: "# Input 1 from previous session heading level 1"; Down Arrow: the message as a "you:" line, a blank line, "# Output 1 from previous session Reply from Claude", a blank line, the reply. `i` again: "# Input 2 from previous session", not the "you:" line. No "Responding" and no chime at startup, only "Ready" with the high ping. Send a message: "# Input 1". Ctrl+Shift+R: "Restarting", then "Ready", and Ctrl+End shows nothing under the system line (no replay, no ticks); another message: "# Input 2".

## 8. Lifecycle

1. Type `/exit`, Enter: "Claude stopped"; the status says "stopped"; the message field still works. Type a word, Enter: "Claude stopped. Ctrl+Shift+R starts it" and the word is still in the field.
2. Ctrl+Shift+R restarts the stopped Claude at once, without a notice; "Ready" again.
2a. With Claude running, Ctrl+Shift+R: the "Force Claude to restart?" notice, whose text ends "Enter: Restart now. Escape: Keep Claude running." Escape: the focus is back where it was and Claude still runs. Ctrl+Shift+R, Enter: "Restarting", then "Ready". With a background command running (ask Claude to run `sleep 120` in the background), the notice starts "Claude has work running in the background (1 shell)."
3. Alt+F4 while the status says "ready": the app closes within two seconds; Task Manager shows no `claude.exe`.
4. Start the app, ask Claude to run `sleep 20` with the Bash tool, and press Alt+F4 while the status says "working". The window stays. NVDA reads "Close AxClaude? read only edit multi line" and the first line "Claude is still working. If you close now, Claude stops in the middle of its work." Down Arrow: the line about carrying on, then "Enter: Close anyway. Escape: Keep working." Tab: "Close anyway button", Tab: "Keep working button". Escape: the notice goes, the focus is back in the message field, NVDA+End still says "working". Send a second message, then Alt+F4 again: the first line now ends "and a message you sent is still waiting for it". Enter: the app closes within two seconds and no `claude.exe` is left. Start it again: the conversation is back.
5. Start the app from a shortcut with no folder argument: it opens the last folder without asking, at the same window size.
6. Sounds, with Options, Sounds, "Chimes: ready, sent, replying, done, question" checked: start the app; a single high ping with "Ready". Then send a message that needs a few tool calls; a short low note plays with "Sent", three rising notes with "Responding", soft single ticks follow while lines arrive, two lower knocks each time a tool starts, with no chime between the tool calls, and three falling notes come with "Done" once the turn has ended. Ask Claude to do something that needs permission: two equal notes with "Claude asks". Options, Sounds, "Ticks for new lines and tool calls" unchecked: no ticks and no tool tick during the next reply; checked again: ticks. The sound option unchecked: no chimes, ticks still there. Ask for a long answer in many short lines ("Write 80 numbered lines"): the ticks stay even and clean to the end, without stutter, and a tick that falls into a chime sounds right after it.
7. Options, Sounds, "Background music while Claude works" checked: send a message that needs a few tool calls; a quiet, slow arpeggio of soft plucked notes starts as the status turns to working and repeats evenly, well under NVDA's speech and under the ticks and the chimes, which sound as before; it stops as the turn ends, just before the three falling notes. Ask Claude for something that needs permission: the music stops as "Claude asks" comes and starts again once the answer has gone. Uncheck the option during a long turn: the music stops at once; check it again: it starts again. Ctrl+Shift+R during a turn, Enter: the music stops with "Restarting". NVDA's speech stays easy to follow over the music. Ctrl+Space in the message field while Claude is idle: "Background music on, nothing is running" and the Sounds item, which shows Ctrl+Space, is checked; Ctrl+Space: "Background music off", unchecked. Ctrl+Space from the conversation during a turn: the music starts with "Background music on"; again: it stops with "Background music off". Plain Space in the conversation does nothing.
8. Options, When Claude is done, "Louder alert when the window is in the background" checked: send a message and switch to another window (Alt+Tab) before Claude is done; a longer, louder call (three rising notes to a held one, twice) comes in place of the three falling notes, and the taskbar button flashes; NVDA says nothing, since the window is not active. Ask for something that needs permission and switch away: the same call in place of the two equal notes or the trill. Stay in the window for the next turn: the three falling notes as before, no alert. Uncheck "Chimes", keep the alert checked, switch away: the alert still comes.

## 10. Claude Code missing, and the installer

1. Start the app with `--claude C:\nowhere\claude.exe`. The notice "Claude Code was not found" takes the place of the conversation with the focus in its text: NVDA reads "Claude Code was not found read only edit multi line" and the first line; Down Arrow reads the path tried, the install command and the way back. Tab reaches "Copy install command", "Open install instructions", "Locate claude.exe..." and "Close". Copy install command: NVDA says it was copied and the notice stays; paste it into Notepad to check. Close: the notice goes, the message field has the focus, the status says "stopped" and the conversation has a "System:" line saying Claude Code was not found. Ctrl+Shift+R shows the notice again; Locate claude.exe opens the standard file picker, and Cancel returns to the notice. Locate again with the real `claude.exe` (usually `%USERPROFILE%\.local\bin\claude.exe`): the notice closes, Claude starts, and the settings file names it under `claudePath` (remove that line afterwards).
2. `.\publish.ps1` from the repository (close the installed AxClaude first, if any). It prints the zip path and the install summary. Start menu: type AxClaude, Enter: the app opens the last folder. File Explorer: a folder's context menu has an "Open with Axit" submenu with AxClaude in it, which opens the app on that folder. A new console: `axclaude` starts the app on the current folder.
